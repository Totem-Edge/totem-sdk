# OMN-039 — Crash recovery could lose the signing watermark after a WOTS signature was released

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/tx-builder@0.7.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia host audit, 2026-11-18 (verified against 51aed956)`

## Context

The double-sign guard was an in-memory watermark plus a pendingProposal field persisted after signing. A crash after signState but before the channel was stored could forget the signed state and allow a different payload at the same sequence. An append-only signing intent is now recorded before the signer is invoked, the signed state is persisted before the ACK, and an unresolved attempt blocks conflicting payloads after restart.

## Impact

Two conflicting states for one sequence could be signed after a restart.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia test
```

**Expected:** A durable signing-intent record exists before the signer is invoked and blocks conflicting payloads after restart.

**Actual:** Fixed: beginSigningAttempt runs before prepare/sign; integration persists before ACK.

**Evidence:**

- packages/omnia/src/guards.ts signing intents
- packages/omnia/src/sign.ts signState
- packages/omnia/src/integration.ts ACK order

## Where to fix

- `packages/omnia/src/guards.ts`
- `packages/omnia/src/sign.ts`
- `packages/omnia/src/integration.ts`
- `packages/omnia-host/src/lifecycle.ts`

### Approach

Persist an append-only signing intent before signing, persist the signed state before the ACK, and block conflicting attempts after restart. Hosts supply a durable journal.

## Constraints (do not violate)

- Never sign two payloads for one sequence.
- An attempt with a released signature can never be abandoned.

## Acceptance criteria

- [ ] Crash injection after signing cannot produce a conflicting signature.
- [ ] An identical payload replay is still allowed.
