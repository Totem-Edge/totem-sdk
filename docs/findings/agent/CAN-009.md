# CAN-009 — Relay recovery discards a link when either side is terminal

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-relay`
**Observed versions:** @totemsdk/omnia-relay@0.7.1
**Source:** `security audit OMN-NEW-003, verified against source at 8fa26907`

## Context

recover() keeps a link only while both HTLCs are pending: terminal(inHtlc) || terminal(outHtlc) causes it to delete the link and remove it from the journal. An outgoing HTLC being fulfilled does not imply the incoming one was fulfilled — settling backwards is a separate later step — so the association is dropped at exactly the point it is still needed.

## Impact

After a restart in the middle of a forward, the link needed to reveal the preimage to the incoming channel is gone. Liquidity on the incoming side stays locked until timeout, and the relay cannot prove the pairing.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-relay test
```

**Expected:** A link is discarded only once the incoming HTLC is settled or the pair is provably unspendable.

**Actual:** terminal(outHtlc) alone deletes the link and its journal entry.

**Evidence:**

- fix proposed in PR #218 (recovery keys on the incoming HTLC only)
- packages/omnia-relay/src/forwarder.ts:289 — const terminal = (h) => !h || h.status !== "pending"
- packages/omnia-relay/src/forwarder.ts:290 — if (terminal(inHtlc) || terminal(outHtlc)) ... remove(hashlock)

## Where to fix

- `packages/omnia-relay/src/forwarder.ts`

### Approach

Split the terminal condition: an outgoing HTLC that is fulfilled means "reveal the preimage to the incoming side", not "done". Discard only when the incoming HTLC is settled or both sides are timed out.

## Constraints (do not violate)

- Do not keep links forever: unresolved links must have a timeout-based exit.
- Do not reveal a preimage without the corresponding fulfilled outgoing HTLC.

## Acceptance criteria

- [ ] recover() returns links whose outgoing HTLC is fulfilled and whose incoming HTLC is still pending.
- [ ] Those links settle backwards after recovery.
- [ ] A link whose incoming HTLC is settled is still removed.
