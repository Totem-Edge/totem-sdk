# CAN-003 — Two unit suites exceed Jest's 5s default timeout under load

**Kind:** sdk-defect  
**Severity:** low  
**Status:** open  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/lookup-node`
**Observed versions:** @totemsdk/omnia-host@0.13.4, @totemsdk/lookup-node@0.4.0
**Source:** `canary core exercise: omnia-host prepare-submit-settle, lookup-node lease`

## Context

The full unit suites fail on a loaded machine because individual tests inherit the 5,000 ms default. omnia-host prepareSettle/submitSettle takes ~15s end to end; lookup-node LEASE_RESERVE passes in 3s alone but exceeds 5s inside the 108s suite. Both pass when given 60s.

## Impact

CI flakiness and false reds: the suites are green on a fast runner and red on a busy one, so a real regression and a slow machine look identical. It also blocks the canary from exercising these packages as part of a full run.

## Reproduce

```bash
pnpm --config.verify-deps-before-run=false --filter @totemsdk/omnia-host test
```

**Expected:** Both suites pass deterministically.

**Actual:** omnia-host: 1 failed / 125 passed (Exceeded timeout of 5000 ms). lookup-node: 1 failed / 70 passed. Both pass with --testTimeout=60000.

**Evidence:**

- tests/unit/omnia-host/src/__tests__/prepare-submit-settle.test.ts:20
- tests/unit/lookup-node/src/__tests__/lease.test.ts:26
- rerun with --testTimeout=60000: 1 passed / 125 skipped, and 1 passed / 70 skipped

## Where to fix

- `tests/jest/omnia-host.cjs`
- `tests/jest/lookup-node.cjs`

### Approach

Give the specific long tests an explicit timeout that reflects their work (settlement signing and a real lease round-trip), rather than raising the default for every test in the repo.

## Constraints (do not violate)

- Do not set a repo-wide 60s default; it hides genuine hangs.
- Do not skip or retry the tests.

## Acceptance criteria

- [ ] The full suites pass twice in a row on a loaded machine.
- [ ] The timeout is scoped to the tests that need it, with a comment saying why.
