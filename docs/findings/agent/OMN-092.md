# OMN-092 — Liquidity receipt consumption is skipped when the receipt is missing

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-pool`
**Observed versions:** @totemsdk/omnia-pool@0.6.2
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-090`

## Context

The payout consumes the liquidity receipt only if nextRegistry.receipts[position.receiptId] exists. For a position that names a receipt id, a missing receipt should be an integrity failure; instead the payout completes without consuming anything.

## Impact

A receipt-backed position can be paid out while its receipt remains unconsumed, so the single-spend marker is silently bypassed. Whether that becomes a double withdrawal depends on other checks the audit cannot assume.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-pool test
```

**Expected:** Every receipt-backed payout requires and atomically consumes the authoritative receipt; a missing one aborts the payout.

**Actual:** Deleting the receipt from the registry lets the payout succeed with no consumption.

**Evidence:**

- packages/omnia-pool/src/withdraw.ts:313-318 — if (receipt) { consume }

## Where to fix

- `packages/omnia-pool/src/withdraw.ts`

### Approach

Treat position.receiptId as mandatory for receipt-backed positions: resolve it, fail if absent, consume it in the same transition, and mint a successor receipt for the remaining balance on a partial withdrawal.

## Constraints (do not violate)

- Fail closed on a missing receipt.
- Consumption and accounting update must be one atomic transition.
- A partial withdrawal must not leave the successor without a receipt.

## Acceptance criteria

- [ ] A receipt-backed payout with no receipt fails.
- [ ] A consumed receipt cannot be consumed again.
- [ ] A partial withdrawal produces a successor receipt for the remainder.
