# OMN-046 — VTXO refresh could overwrite its own input because the id excluded the epoch

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-vtxo`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

computeVtxoId ignored the epoch, so reusing the mint nonce made the refreshed output id equal to the input id and the host stored the replacement over the consumed record. Replacement ids now include the epoch, and a refresh that would reproduce its input id is rejected.

## Impact

A consumed VTXO id could become active again, making proof and status history ambiguous.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-vtxo test
```

**Expected:** A refresh always produces a distinct id.

**Actual:** Fixed: epoch is part of replacement ids; same-id refreshes throw.

**Evidence:**

- packages/omnia-vtxo/src/commitment.ts computeVtxoId
- packages/omnia-vtxo/src/refresh.ts

## Where to fix

- `packages/omnia-vtxo/src/commitment.ts`
- `packages/omnia-vtxo/src/refresh.ts`

### Approach

Include the epoch in replacement ids and reject an output id equal to the input.

## Constraints (do not violate)

- Mint ids stay stable; only replacements carry an epoch.

## Acceptance criteria

- [ ] Refreshing with the mint nonce yields a new id.
- [ ] The consumed record is preserved.

## Tests that prove it
