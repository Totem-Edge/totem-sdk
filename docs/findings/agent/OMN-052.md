# OMN-052 — Splice-in proposals omitted the additional coin address

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-splice`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

proposeSpliceIn accepted a coin id and amount but no address, and the builder wrote an empty address placeholder. The address is now a required parameter, carried into the proposal, and the host resolves and verifies the coin (owner, amount, unspent) before proposing.

## Impact

The standard splice-in path produced transaction bytes that did not describe the added coin.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-splice test
```

**Expected:** A splice-in carrying no address is rejected; a real address is encoded.

**Actual:** Fixed: the builder fails closed and the host verifies the coin.

**Evidence:**

- packages/omnia-splice/src/splice-tx.ts
- packages/omnia-splice/src/splice.ts proposeSpliceIn
- packages/omnia-host/src/api/methods.ts prepareSpliceIn

## Where to fix

- `packages/omnia-splice/src/splice-tx.ts`
- `packages/omnia-splice/src/splice.ts`
- `packages/omnia-host/src/api/methods.ts`

### Approach

Require the address, carry it through the proposal, and verify the coin on chain.

## Constraints (do not violate)

- Never serialize a placeholder address.

## Acceptance criteria

- [ ] Missing address throws.
- [ ] The encoded input carries the real address.
