# OMN-103 — Cross-token locality is decided from the inbound channel only

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia-router`
**Observed versions:** @totemsdk/omnia-host@0.16.0, @totemsdk/omnia-router@0.6.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-101
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-101 (omnia-host/src/api/methods.ts:4077-4092)`

## Context

The host decides whether every hop is local from each hop's channelId. A swap hop carries inboundChannelId and outboundChannelId; the lease map handles both, but the locality check does not verify that the outbound side is local. The reporter corrected the earlier claim that swap hops lack channelId.

## Impact

A route in which both channels are local can be classified distributed and rejected by the unsupported-distributed-swap guard.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Locality covers both sides of a swap hop.

**Actual:** Only the inbound side is considered.

**Evidence:**

- methods.ts:4077-4092

## Where to fix


### Approach

Check inboundChannelId and outboundChannelId for swap hops when deciding locality.

## Constraints (do not violate)

- Do not treat a partial swap as local.
- Keep the lease map construction unchanged.

## Acceptance criteria

- [ ] A fully local cross-token route executes.
- [ ] A route with a remote outbound side is classified distributed.
