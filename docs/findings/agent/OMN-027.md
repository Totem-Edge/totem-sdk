# OMN-027 — The advertised N-party factory API coordinates with only one remote participant

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/omnia-vtxo@0.9.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia host signing audit, 2026-11-18 (verified against 997b7f40)`

## Context

The host coordinates a factory opening with exactly one remote peer, so it now refuses anything but two distinct participants with an explicit error instead of advertising N-party coordination it cannot perform. Library builders (buildFactoryOpening) remain N-capable; only the host API is scoped.

## Impact

A caller can no longer create a factory that only one remote learned about, or that reuses one party's signer for another. N-party factories are not available through the host until multi-peer coordination lands.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Every factory participant is coordinated by identity and every signature is verified.

**Actual:** assertTwoPartyFactory rejects N>2 and duplicate participants on both factory paths (tests/unit/omnia-host/src/__tests__/peer-guards.test.ts).

**Evidence:**

- packages/omnia-host/src/api/methods.ts lines around 1653, 1747, 3160, 3225, 3292

## Where to fix

- `packages/omnia-host/src/api/methods.ts`

### Approach

Iterate all remote participants, connect by identity, collect and verify each signature, and persist N-party progress so restarts can resume.

## Constraints (do not violate)

- Do not reuse one participant’s signer for another.
- Fail closed when any participant is missing.

## Acceptance criteria

- [ ] A 3-party factory gathers all three signatures.
- [ ] Progress survives a restart.
