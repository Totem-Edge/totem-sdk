# CAN-014 — The watchtower is implemented and exported but never started by the host

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-host@0.13.4
**Source:** `security audit OMN-NEW-008, verified against source at 8fa26907`

## Context

createChannelWatchService exists with detection and retry logic and is exported from the package index, but no code calls it: createOmniaHost().start() contains no reference to it. Its close detection also keys on the original funding coin being spent, which cannot distinguish a unilateral close from an update or splice, and it adds the channel to a persistent closed set.

## Impact

A host holding funds runs with no automated response to a unilateral close: no contest transaction is produced before the deadline. Where the service is used manually, a normal update can be misread as a close and suppress later events.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** The host starts a chain-aware watcher that tracks successive channel coins and deadlines.

**Actual:** Only the definition and the export exist; lifecycle.ts has no watcher.

**Evidence:**

- fix proposed in PR #218 (watch service started by the host; successor-aware close detection)
- packages/omnia-host/src/watch.ts:69 — export function createChannelWatchService
- packages/omnia-host/src/index.ts:50 — export only
- packages/omnia-host/src/lifecycle.ts — no reference to the watch service

## Where to fix

- `packages/omnia-host/src/lifecycle.ts`
- `packages/omnia-host/src/watch.ts`

### Approach

Start the watcher in host.start() and stop it in close(). Track the current channel coin per sequence rather than the original funding coin, distinguish update from close by the spending transaction, and handle reorgs and contest deadlines.

## Constraints (do not violate)

- Do not treat "funding coin spent" as equivalent to "unilateral close".
- Do not let the persistent closed set suppress later events for a channel that is still live.

## Acceptance criteria

- [ ] Host startup starts the watcher and shutdown stops it.
- [ ] A simulated unilateral close triggers the contest path before the deadline.
- [ ] A normal state update or splice does not mark the channel closed.
