# OMN-001 — Peer-scoped finalization stores peer-supplied factory, channel and splice state

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** open  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia-factory`
**Tracked as:** `CAN-019` — this id is the audit's alias; the canonical entry owns the fix.
**Observed versions:** @totemsdk/omnia-host@0.13.4, @totemsdk/omnia-factory@0.7.1
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)

> Aliased to CAN-019, which tracks identifier-only finalization guards. CAN-007 covers the unsolicited-message half; this entry adds the factory active→active / opening→opening branches.
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-001`

## Context

FACTORY_FINALIZED opening→active is validated, but two branches are not: active→active returns the incoming object wholesale, and opening→opening accepts additional pending signatures without verifying them. In the host, VC_FINALIZED writes `payload.factory` to the factory store after checking only factoryId and sequence+1, SPLICE_FINALIZED writes `payload.channel` after binding checks that never recompute balances or signatures, and FACTORY_CLOSE_FINALIZED marks a known factory closed without any settlement evidence.

## Impact

A participant (or a compromised peer) can replace another participant's locally accepted factory state, channel state or closure status. Fund loss requires a downstream path that trusts the stored object; inconsistent accounting and stuck funds are reachable without one.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Every peer finalization message is rejected unless the resulting state can be rebuilt from local state plus a transition that verifies.

**Actual:** assertFactoryFinalized returns `{...incoming}` for active→active, and lifecycle.ts stores `payload.factory` and `payload.channel` after identity/sequence checks only.

**Evidence:**

- packages/omnia-factory/src/factory.ts: assertFactoryFinalized active→active and opening→opening branches
- packages/omnia-host/src/lifecycle.ts: `factories.set(payload.factory.factoryId, payload.factory)`
- packages/omnia-host/src/lifecycle.ts: `channelStore.set(channel.channelId, channel)` for SPLICE_FINALIZED
- packages/omnia-host/src/lifecycle.ts: FACTORY_CLOSE_FINALIZED sets status closed unconditionally

## Where to fix

- `packages/omnia-host/src/peer-guards.ts`
- `packages/omnia-host/src/lifecycle.ts`
- `packages/omnia-factory/src/factory.ts`

### Approach

Derive the expected object locally for every finalization message: rebuild the factory/channel transition from the local copy, verify every participant signature and the state commitment, then store the rebuilt object rather than the peer payload. Reject unknown added signatures. Require a settlement artifact bound to the factory before accepting a close.

## Constraints (do not violate)

- Do not accept a whole replacement object from a peer on any message type.
- Do not weaken the opening→active checks that already exist.
- Keep the wire format unchanged; this is a validation-boundary fix.
- A rejected message must leave the store byte-identical.

## Acceptance criteria

- [ ] A matrix test covers every peer finalization handler against sequence, allocation, signature, identity and replay mutations; every case is rejected and the store is unchanged.
- [ ] Factory active→active validates sequence progression and the state log before storing.
- [ ] Opening→opening verifies any signature it did not already hold.
- [ ] FACTORY_CLOSE_FINALIZED requires finality evidence bound to the factory id and settlement.
- [ ] The valid-path cases still succeed.
