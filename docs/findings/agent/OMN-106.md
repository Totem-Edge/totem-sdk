# OMN-106 — VTXO epoch admission has a check-then-sign race

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** open  
**Packages:** `@totemsdk/vtxo`
**Observed versions:** @totemsdk/vtxo@0.10.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-104
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-104 (vtxo/src/epoch-authority.ts:111-153)`

## Context

append() verifies the receipt, loads state, checks spent inputs, signs the epoch commitment and appends. The checks and the signing are separated by awaits with no reservation, so two concurrent appends can both pass the spent-input check and sign conflicting spends or roots.

## Impact

The epoch authority is the durable single-spend guard for receipts; admitting two conflicting transitions makes it ineffective.

## Reproduce

```bash
pnpm --filter @totemsdk/vtxo test
```

**Expected:** Inputs and the epoch transition are reserved atomically before a signature is produced.

**Actual:** Checks and signing are separate steps.

**Evidence:**

- epoch-authority.ts:111-153 (append)

## Where to fix


### Approach

Reserve inputs and the epoch transition with a revision-checked durable transaction before signing; conflicting requests fail before the signature.

## Constraints (do not violate)

- Do not sign before the reservation commits.
- Keep the journal append idempotent per receipt id.

## Acceptance criteria

- [ ] Two concurrent receipts spending the same input admit one.
- [ ] No signature exists for a rejected transition.
