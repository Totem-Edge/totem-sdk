# CAN-024 — Omnia writes atom amounts with MiniNumber scale 0, encoding channel values 10^44 times too large

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia`, `@totemsdk/omnia-host`, `@totemsdk/chain-provider`, `@totemsdk/core`
**Observed versions:** @totemsdk/omnia@2.4.4, @totemsdk/omnia-host@0.13.6, @totemsdk/chain-provider@0.3.3
**Fixed in:** 9213dd32

## Context

Minima has one amount type, `MiniNumber`. Its JSON form is decimal MINIMA text
(`"0.2"` — `Coin.toJSON` calls `MiniNumber.toString()`, which is
`stripTrailingZeros().toPlainString()`). Its binary form is
`(unscaled, scale)` with value = `unscaled × 10^-scale`
(`MiniNumber.writeDataStream`). `MAX_DECIMAL_PLACES = 64 - 20 = 44`, so
1 MINIMA = 10^44 atoms.

Omnia keeps channel maths in atoms, but `serializeCoinForMinima` wrote the atom
integer with the default scale 0. A 0.2 MINIMA channel was therefore encoded as
`(2×10^43, 0)` = 2×10^43 MINIMA. At the same time, only `MinimaRpcProvider`
normalised `amount` to atoms; `HostedProvider`, `LookupClientProvider` and
`CompositeProvider` stayed decimal, so one interface had two units.

## Impact

- Every non-trivial funding/update/settlement draft is rejected by
  `Transaction.checkValid()`: `MiniNumber.isValidMinimaValue()` requires
  `0 < amount <= 1,000,000,000`.
- `openChannel` failed earlier at `Cannot convert 0.2 to a BigInt`, which
  masked the encoding fault.
- Decimal consumers (tx-builder selection/serialisation, the extension's
  `TOTEM_GET_COINS`, edge-adapters and realtime balances) are inflated by
  10^44 when a provider returns atoms; a composite fallback flips units
  mid-application.

## Reproduce

```bash
node - <<'NODE'
const { buildFundingTx, omniaDraftToCanonicalMinimaBytes } =
  require('./packages/omnia/dist/cjs/transactions.js');
const atoms = 2n * 10n ** 43n; // 0.2 MINIMA
const draft = buildFundingTx('RETURN TRUE', '0x' + 'aa'.repeat(32), atoms, '0x00', 0,
  ['0x' + 'bb'.repeat(32)], [atoms], ['0x' + 'cc'.repeat(32)]);
const b = Buffer.from(omniaDraftToCanonicalMinimaBytes(draft));
// walk to the first input amount: [scale][len][unscaled]
console.log(b.slice(3 + 5 + 36, 3 + 5 + 36 + 21).toString('hex'));
NODE
```

**Expected:** amount `MiniNumber(unscaled = 2×10^43, scale = 44)` → Java reads 0.2 MINIMA, valid.

**Actual:** `MiniNumber(unscaled = 2×10^43, scale = 0)` → Java reads 2×10^43 MINIMA, invalid.

**Evidence:**

- `minima-global/Minima objects/Coin.java:239` — JSON amount is decimal text
- `minima-global/Minima objects/base/MiniNumber.java:31-49` — 44 decimal places, `MINI_UNIT = 1E-44`
- `minima-global/Minima objects/base/MiniNumber.java:287-299` — `[scale][length][unscaled]`
- `minima-global/Minima objects/Transaction.java:165` — validity bound
- `packages/omnia/src/transactions.ts: serializeCoinForMinima`
- `packages/chain-provider/src/providers/minima-rpc.ts` vs `hosted.ts` / `lookup-client.ts`

## Where to fix

- `packages/core/src/amount.ts` (unit helpers)
- `packages/chain-provider/src/providers/minima-rpc.ts`
- `packages/chain-provider/src/types.ts`
- `packages/omnia/src/transactions.ts`, `channel.ts`, `state-vars.ts`, `kissvm.ts`
- `packages/omnia/rust/src/serialize.rs`, `commitment.rs`

### Approach

Providers return node-native decimal text; `@totemsdk/core` owns
`amountToAtoms` / `atomsToAmount` / `coinAmountAtoms`; Omnia converts once at
its boundary and writes every coin amount as
`MiniNumber(unscaled = atoms, scale = 44)`. Value-bearing state ports (HTLC
locked amount, vault value, treasury cap/spent, membership pool, asset
balances, meter unit price/payment) use the same scale, and the scale is bound
into the signed state commitment so it cannot be re-encoded underneath a valid
signature. The Rust/WASM mirror uses arbitrary-precision integers and the same
rules.

## Constraints (do not violate)

- Do not normalise units inside one `ChainStateProvider` implementation.
- Do not write atom amounts with scale 0 anywhere.
- Counters, sequences, block heights and indexes stay scale 0.
- Bind the state-port scale in the commitment.

## Acceptance criteria

- [x] Every provider returns the same unit, and a composite fallback cannot change it.
- [x] A 0.2 MINIMA funding draft decodes to scale 44 / 0.2 and passes the Java validity bound.
- [x] Value-bearing state ports round-trip at scale 44; counters stay scale 0.
- [x] Rust/WASM digest and commitment parity hold.
