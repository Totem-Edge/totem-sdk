# OMN-087 — Exit entitlement verification checks that a pool epoch exists, not that it publishes this root

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-vtxo`
**Observed versions:** @totemsdk/omnia-vtxo@0.9.0
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-085`

## Context

verifyVtxoExitEntitlement() compares the entitlement root with the VTXO's own proof root, then — when an authoritative pool is supplied — only checks that a pool.epochRoots entry exists for the entitlement's epoch number. The published root for that epoch is never compared, and the decoded payout output's token id is never checked against the entitlement token.

## Impact

An entitlement can pass every local check while disagreeing with the authoritative pool's published commitment, depending entirely on the injected witness verifier. A payout in the wrong asset is accepted as long as the amount and address match.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-vtxo test
```

**Expected:** Entitlement, decoded transaction, inclusion proof, published epoch root and payout token are bound to the same authoritative pool commitment.

**Actual:** A pool whose epochRoots lists the epoch with a different root still verifies, and a payout output in a different token passes.

**Evidence:**

- packages/omnia-vtxo/src/exit-entitlement.ts:143-180 — pool checks
- packages/omnia-vtxo/src/exit-entitlement.ts:160-166 — some(entry => entry.epoch === entitlement.epoch)
- packages/omnia-vtxo/src/exit-entitlement.ts:120-133 — payout address and amount, no token check

## Where to fix

- `packages/omnia-vtxo/src/exit-entitlement.ts`

### Approach

Resolve the published root for the entitlement epoch and require equality with the entitlement root. Compare the decoded payout token id with the entitlement token id. Require an inclusion proof for the entitlement leaf when a pool root is available.

## Constraints (do not violate)

- Do not weaken the existing VTXO-local root comparison.
- Historical epochs must verify against their own published root.
- Fail closed when the authoritative pool does not publish the epoch.

## Acceptance criteria

- [ ] An epoch published with a different root fails verification.
- [ ] A payout in the wrong token fails verification.
- [ ] A correct entitlement in a historical epoch still verifies.
- [ ] An unpublished epoch fails rather than being skipped.
