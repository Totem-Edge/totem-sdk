# OMN-114 — An allocation can be released without proof of capital recovery

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-pool`
**Observed versions:** @totemsdk/omnia-pool@0.7.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-112; fixed by parking a release as settling without verified recovery evidence: availability is unchanged until confirmAllocationRecovery accepts evidence covering the amount, rebalance refuses to redeploy unrecovered capital, and the host release RPC requires a recovery verifier
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-112 (omnia-pool/src/allocate.ts:198-229)`

## Context

releaseAllocation marks the allocation released and restores available liquidity by accounting only. It does not verify that the channel settled, the factory allocation was recovered or obligations were discharged.

## Impact

Released accounting is treated as recovered capital, so liquidity can be redeployed while the funds are still committed.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-pool test
```

**Expected:** Release requires evidence of recovery; the registry distinguishes releasing, pending settlement and recovered.

**Actual:** Release is an accounting operation.

**Evidence:**

- allocate.ts:198-229

## Where to fix


### Approach

Add a settlement-evidence gate to release and a pending-settlement state that does not count as available.

## Constraints (do not violate)

- Do not count pending settlement as available liquidity.
- Keep the release recoverable after a restart.

## Acceptance criteria

- [ ] A release without recovered capital is refused or parked.
- [ ] Availability only increases after verified recovery.
