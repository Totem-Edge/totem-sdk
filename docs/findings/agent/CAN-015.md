# CAN-015 — Router rollback cannot release HTLCs early and reports failure as if liquidity were returned

**Kind:** sdk-defect  
**Severity:** medium  
**Status:** in-progress  
**Packages:** `@totemsdk/omnia-router`
**Observed versions:** @totemsdk/omnia-router@0.4.1
**Source:** `security audit OMN-NEW-009, verified against source at 8fa26907`

## Context

On a failed multi-hop payment the router calls timeoutHTLC on each still-pending lock and swallows every error. timeoutHTLC deliberately throws while the chain tip is below the HTLC timeout block, which is the normal case for a payment that just failed. So the rollback releases nothing, yet the failure result and the in-code comment ("stranded HTLCs are never left behind silently") imply it did.

## Impact

Liquidity stays locked until the timeout block, and callers have no state that says so. A retry can fail for lack of capacity that is not actually gone. This is a recovery-state and API-contract defect, not direct fund theft.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-router test
```

**Expected:** A failed payment records explicit refund-pending locks and releases them once the timeout is valid.

**Actual:** cancelHtlcs catches and ignores the "has not yet timed out" error; the caller sees only a failure.

**Evidence:**

- fix proposed in PR #218 (pendingRefunds on failure; cancelPayment throws PendingRefundError)
- packages/omnia-router/src/execute.ts:52 — try { await ops.timeoutHTLC(...) } catch { /* best-effort */ }
- packages/omnia/src/htlc.ts:437 — throw when currentBlock < htlc.timeoutBlock
- packages/omnia-router/src/execute.ts:68 — comment claims stranded HTLCs are never left behind

## Where to fix

- `packages/omnia-router/src/execute.ts`
- `packages/omnia-router/src/types.ts`

### Approach

Persist refund-pending locks with their timeout blocks, expose that state in the payment result, and retry when the timeout becomes valid. Distinguish refunded from refund-pending rather than collapsing both into a generic failure.

## Constraints (do not violate)

- Do not claim liquidity was released when timeoutHTLC threw.
- Do not bypass the timeout guard to force an early release.

## Acceptance criteria

- [ ] A failed payment reports which locks remain pending and until which block.
- [ ] A retry after the timeout block releases them.
- [ ] The success path is unchanged.
