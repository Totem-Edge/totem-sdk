# OMN-104 — The S4 harness can report S4_PASS without asserting settlement

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `null`
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-102
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-102 (scripts/omnia-s4-cross.mjs:207-246)`

## Context

The harness logs the settlement and close responses and then constructs a result with pass: true. It does not assert that settlement and closure succeeded or that the expected payout outputs exist on chain, so an RPC response containing a logical failure can reach S4_PASS.

## Impact

The automatic pass indicator cannot be relied on as evidence. The documented on-chain outputs from the 25 November run stand; the harness result alone does not prove them.

## Reproduce

```bash
pnpm exec node scripts/omnia-s4-cross.mjs --help
```

**Expected:** PASS requires balance conservation, expected recipient balances, matching peer sequences and confirmed closure.

**Actual:** pass: true is constructed after logging.

**Evidence:**

- omnia-s4-cross.mjs:236 (pass: true)
- omnia-s4-cross.mjs:239 (console.log S4_PASS)

## Where to fix


### Approach

Assert the final invariants before printing S4_PASS: conservation, recipient balances, sequences, settlement outputs, predecessor consumption and closure on both hosts.

## Constraints (do not violate)

- Do not weaken existing assertions.
- Keep the harness usable without live infrastructure (skip, not pass).

## Acceptance criteria

- [ ] A logical failure in any step yields a non-zero exit.
- [ ] S4_PASS implies every asserted invariant held.
