# OMN-031 — The release gate can ignore an unresolved critical finding through an alias

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia-factory`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/chain-provider@0.4.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia host audit, 2026-11-18 (verified against 41106016 / 997b7f4)`

## Context

The SDK gate skipped any finding with a canonical id, without checking whether the canonical row was still blocking at the same or higher severity. OMN-001 (critical, open) was hidden behind CAN-019 (high, fixed). The gate now suppresses an alias only when its canonical row is blocking at the same or higher severity; a regression test is still pending.

## Impact

A critical unresolved finding could be excluded from the release-blocking calculation.

## Reproduce

```bash
pnpm run findings:gate
```

**Expected:** An open alias blocks at its own severity unless a blocking canonical row covers it.

**Actual:** Fixed in verify-findings-gate.mjs and the canary gate; OMN-001 now appears in the blocking set. Regression test pending.

**Evidence:**

- scripts/verify-findings-gate.mjs alias loop
- artifacts/canary/src/findings/gate.ts alias loop
- OMN-001 canonical CAN-019

## Where to fix

- `scripts/verify-findings-gate.mjs`
- `artifacts/canary/src/findings/gate.ts`

### Approach

An alias inherits blocking status from the most restrictive unresolved row in its equivalence group; a fixed canonical row never suppresses an open alias.

## Constraints (do not violate)

- Do not weaken the gate to make a release pass.

## Acceptance criteria

- [ ] OMN-001 blocks while open.
- [ ] A genuinely duplicated alias is counted once.

## Tests that prove it
