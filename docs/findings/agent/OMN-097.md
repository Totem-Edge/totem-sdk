# OMN-097 — No consensus-enforced channel domain: identical parties and delay share a script

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** open  
**Packages:** `@totemsdk/omnia`, `@totemsdk/omnia-splice`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@4.0.0, @totemsdk/omnia-splice@0.4.0, @totemsdk/omnia-host@0.16.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-095
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-095 (omnia/src/script.ts:43-92, omnia/src/transactions.ts:400-458)`

## Context

The eltoo funding script is derived from the two public keys and the contest delay, with no unique channel identifier. The update input floats via COINID_ELTOO, and the covenant does not check that the successor's channel identity matches the coin being spent. Multiple channels between the same parties therefore share a script address, and the signed state commitment is not bound by the script.

## Impact

A signed artifact may be executable in a sibling channel domain. The audit did not demonstrate a replay, but the isolation invariant is absent from the covenant, which is the only place it can be enforced.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia test
```

**Expected:** Every continuation is bound to an immutable channel domain identifier enforced by the script.

**Actual:** The script pins only settlement (port 100) and sequence (port 101).

**Evidence:**

- script.ts:77-79 (STATE(100)/STATE(101) only)
- transactions.ts COINID_ELTOO floating input

## Where to fix


### Approach

Add an immutable channel domain id to the funding script or a dedicated state port that every continuation must preserve; add a regression test on Hawk and the Java node.

## Constraints (do not violate)

- Changing the funding script is a wire change: version it.
- Do not rely on an off-chain commitment alone.
