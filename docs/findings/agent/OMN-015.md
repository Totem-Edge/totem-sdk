# OMN-015 — Watchtower callbacks only emit observations; nothing protects the channel

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`
**Tracked as:** `CAN-021` — this id is the audit's alias; the canonical entry owns the fix.
**Observed versions:** @totemsdk/omnia-host@0.13.4
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-015`

## Context

The watch handlers now act. A unilateral close is contested by broadcasting the latest signed close package (funding-coin proof plus script proof) with startUnilateralClose, recording the contest window. An expiring HTLC is timed out with timeoutHTLC, persisted, and the signed timeout state is sent to the counterparty. Both paths emit an observation with the outcome and leave the finding unprocessed if the action fails. Residual: the host-level simulation of both actions is still the acceptance test to add.

## Impact

A unilateral close or an expiring HTLC is noticed but not acted on. The window to contest or claim can pass while the host is healthy.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** A unilateral-close finding triggers the contest path (or an explicit, recorded refusal).

**Actual:** A close broadcasts a contest transaction (or fails closed) and an expiring HTLC is timed out and propagated; observed decisions are recorded as observation events.

**Evidence:**

- packages/omnia-host/src/lifecycle.ts: both callbacks contain a single `observation.emit`
- packages/omnia-host/src/watch.ts: comment claims the host wires contest logic

## Where to fix

- `packages/omnia-host/src/lifecycle.ts`
- `packages/omnia-host/src/watch.ts`

### Approach

Implement (or explicitly refuse and surface) the protective action: contest with the latest signed state, timeout or fulfil an expiring HTLC, and record the decision. Make the successor check bind to the channel state rather than address+amount alone.

## Constraints (do not violate)

- Do not claim watchtower support while only emitting events.
- A protective action must be idempotent across restarts.

## Acceptance criteria

- [ ] A simulated unilateral close causes a contest broadcast (or a recorded, operator-visible refusal).
- [ ] An expiring HTLC causes timeout/fulfil before the deadline.
