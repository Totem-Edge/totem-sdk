# OMN-013 — Link journal serialization is in-process only

**Kind:** sdk-defect  
**Severity:** medium  
**Status:** open  
**Packages:** `@totemsdk/omnia-relay`
**Tracked as:** `CAN-022` — this id is the audit's alias; the canonical entry owns the fix.
**Observed versions:** @totemsdk/omnia-relay@0.7.1
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (reported, not reproduced)
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-013`

## Context

Journal updates are serialized within one process. The duplicate-forward check runs before signing, so two processes sharing a store can both reserve the same payment.

## Impact

Two relay processes can both forward one incoming HTLC, producing a double settlement attempt.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-relay test
```

**Expected:** Two processes competing for the same hashlock: one forward.

**Actual:** No cross-process reservation.

**Evidence:**

- packages/omnia-relay/src/link-journal.ts

## Where to fix

- `packages/omnia-relay/src/link-journal.ts`

### Approach

Reserve atomically in the shared store (CAS on a per-hashlock key) before signing, and release on failure.

## Constraints (do not violate)

- Do not rely on a process-local mutex.
- A crashed reservation must be reclaimable after a bounded lease.

## Acceptance criteria

- [ ] Two processes: exactly one reservation succeeds.
- [ ] Expired reservations are reclaimable without double settlement.
