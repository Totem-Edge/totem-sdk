# OMN-108 — Signing admission reads an unreadable journal as "no history"

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@4.0.0, @totemsdk/omnia-host@0.16.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-106; The audit is right that OMN-039 was incompletely closed: the durable journal was opt-in.
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-106 (omnia/src/guards.ts:217-249)`

## Context

beginSigningAttempt caught every journal read error and continued with an empty history, then recorded the intent and allowed signing. The journal also defaulted to an in-memory implementation, so durability existed only if the host installed one. Read, conflict check and write were separate operations.

## Impact

A storage fault licenses a second WOTS signature at a sequence that may already be signed — leaf reuse. This undermines OMN-039.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia test
```

**Expected:** An unavailable journal refuses the signature; admission is serialised; the host refuses to run on an in-memory journal without warning.

**Actual:** Read errors were swallowed and admission was unsynchronised.

**Evidence:**

- guards.ts:224-230 (catch => existing = [])
- guards.ts:193 (memory default)

## Where to fix


### Approach

Fail closed on read and write errors, serialise admission per channel, expose whether the journal is in-memory and warn at host startup.

## Constraints (do not violate)

- Do not weaken double-sign detection.
- Keep retries of the same payload idempotent.

## Acceptance criteria

- [ ] An unreadable journal refuses signing.
- [ ] Concurrent different payloads at one sequence admit one.
- [ ] A host warns when only the memory journal is installed.
