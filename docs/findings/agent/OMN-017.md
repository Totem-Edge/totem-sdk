# OMN-017 — Factory escape block is derived from the local chain tip

**Kind:** sdk-defect  
**Severity:** medium  
**Status:** open  
**Packages:** `@totemsdk/omnia-factory`
**Observed versions:** @totemsdk/omnia-factory@0.7.1
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-017`

## Context

buildFactoryOpening computes `escapeBlock = tip.block + FACTORY_ESCAPE_DELAY_BLOCKS` and puts it in the funding script, while the pending commitment excludes it. Two hosts at different heights therefore derive different scripts for the same proposal, and the finalized terms comparison rejects the opening.

## Impact

Factories fail to open whenever participants are not at the same tip. This is a liveness defect, not a divergence: the differing script is detected rather than silently accepted.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-factory test
```

**Expected:** Both participants derive the same funding script and identity from a proposal.

**Actual:** escapeBlock differs with the tip, so fundingScript and fundingAddress differ.

**Evidence:**

- packages/omnia-factory/src/factory.ts: `const escapeBlock = tip.block + FACTORY_ESCAPE_DELAY_BLOCKS`
- packages/omnia-factory/src/factory.ts: pendingCommitment built without state variables

## Where to fix

- `packages/omnia-factory/src/factory.ts`

### Approach

Derive the escape block from an agreed anchor (the proposal carries it, or it is the funding coin height) and commit to it in the pending commitment so a mismatch is impossible rather than merely detected.

## Constraints (do not violate)

- Do not weaken the escape delay.
- The commitment must cover every script-affecting input.

## Acceptance criteria

- [ ] Two hosts at different tips derive the same funding script from one proposal.
- [ ] A changed escape block changes the commitment.

## Tests that prove it
