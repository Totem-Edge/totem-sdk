# OMN-049 — Prepared-signature submissions did not prevent one-time WOTS key reuse

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

submitPay accepted wallet-supplied update and settlement indices without checking they differ or were previously consumed. It now rejects identical leaves and, when a durable leaf registry is configured, rejects a leaf reused for a different digest.

## Impact

One WOTS leaf could sign two different transaction digests.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Update and settlement signatures use disjoint, unconsumed leaves.

**Actual:** Fixed: indices must differ and consumed leaves are tracked per digest.

**Evidence:**

- packages/omnia-host/src/api/methods.ts submitPay
- packages/omnia/src/sign.ts finalizeStateUpdateWithIndices

## Where to fix

- `packages/omnia-host/src/api/methods.ts`

### Approach

Require disjoint indices and record consumed leaves against their digest.

## Constraints (do not violate)

- A leaf may only ever sign one digest.

## Acceptance criteria

- [ ] Equal indices are rejected.
- [ ] A leaf reused for another digest is rejected.

## Tests that prove it

- `tests/unit/omnia-host/src/__tests__/prepare-submit-pay.test.ts`
