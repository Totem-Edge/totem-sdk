# OMN-033 — One unspent funding coin can support multiple LP commitments

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/omnia-pool`, `@totemsdk/liquidity-bond`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/chain-provider@0.4.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia host audit, 2026-11-18 (verified against 41106016 / 997b7f4)`

## Context

depositToPool verifies that the referenced coin is currently unspent but does not reserve or consume it, and the registry indexes commitments by commitment id rather than unique funding coin. The same UTXO can satisfy multiple deposits.

## Impact

The same economic collateral can be counted multiple times, inflating pool capital and LP entitlements.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-pool test
```

**Expected:** A funding coin can back at most one active commitment.

**Actual:** A second deposit with the same underlyingUtxoRef creates a second position/receipt.

**Evidence:**

- packages/omnia-pool/src/deposit.ts
- packages/liquidity-bond/src/commitment.ts
- packages/liquidity-bond/src/registry.ts

## Where to fix

- `packages/liquidity-bond/src/registry.ts`
- `packages/liquidity-bond/src/commitment.ts`
- `packages/omnia-pool/src/deposit.ts`

### Approach

Add a durable unique funding-coin reservation/consumption index scoped by chain and asset; reject duplicate active commitments and reconcile if the coin is spent/reorged.

## Constraints (do not violate)

- Do not rely on a transient unspent lookup as uniqueness.

## Acceptance criteria

- [ ] A duplicate funding coin is rejected across pools/positions.
- [ ] A spent/reorged coin invalidates the reservation.
