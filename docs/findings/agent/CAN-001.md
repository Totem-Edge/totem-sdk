# CAN-001 — Channel funding draft silently drops the unspent part of the funding coin

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/omnia`, `@totemsdk/omnia-host`, `@totemsdk/tx-builder`
**Observed versions:** @totemsdk/omnia@2.4.2, @totemsdk/omnia-host@0.13.4, @totemsdk/tx-builder@0.3.1
**Source:** `artifacts/canary/src/composition/__tests__/CrossPackage.test.ts`

## Context

buildFundingTx takes explicit input amounts but always emits exactly one output (the channel coin). It neither returns change nor checks that inputs cover outputs, and buildChannelOpening passes the whole funding coin. Opening a channel from a coin larger than localAmount + remoteAmount therefore produces a draft whose inputs exceed its outputs by the unspent remainder. tx-builder buildTransaction does not check conservation either, so nothing fails until a node rejects the unbalanced transaction.

## Impact

Reachable from the RPC surface: omnia-host forwards fundingCoinId unchanged, so any wallet that does not pre-select an exactly-sized coin fails to open a channel with an opaque node rejection. No funds are lost (the node refuses the transaction) but the failure is late and misattributed.

## Reproduce

```bash
cd artifacts/canary && pnpm composition
```

**Expected:** The draft either pays the remainder back to the funding coin address (change output) or throws when sum(inputs) > totalValue.

**Actual:** The draft contains a single output. inputs sum 1500 while outputs sum 1000, and no layer rejects it. Recorded as a node:test TODO so it stays visible without failing the gate.

**Evidence:**

- CANARY FINDING: an over-funded funding draft is neither changed nor rejected (TODO)
- packages/omnia/src/transactions.ts: buildFundingTx
- packages/omnia/src/channel.ts: buildChannelOpening passes fundingCoin.amount as the input
- packages/omnia-host/src/api/methods.ts: prepareOpenChannel forwards fundingCoinId
- packages/tx-builder/src/build.ts: buildTransaction has no conservation check

## Where to fix

- `packages/omnia/src/transactions.ts`
- `packages/omnia/src/channel.ts`
- `packages/tx-builder/src/build.ts`

### Approach

Add a change output to the input coin address in buildFundingTx when sum(inputs) > totalValue, or reject the draft with a clear error. Do both at the right layers: omnia owns channel funding semantics, tx-builder should refuse to serialise an unbalanced transaction rather than deferring to the node.

## Constraints (do not violate)

- Do not change the funding output state contract: STATE(100)=false, STATE(101)=0.
- Do not change computeOmniaTxDigest / canonical byte semantics.
- Do not mask this in the canary, in omnia-host, or with a coin pre-selection workaround.
- Keep the single-input fast path byte-identical when the input equals totalValue.

## Acceptance criteria

- [ ] buildFundingTx returns a change output to the funding coin address when inputs exceed totalValue.
- [ ] buildFundingTx (or buildChannelOpening) throws when inputs are less than totalValue.
- [ ] tx-builder buildTransaction rejects a draft whose input sum is below its output sum.
- [ ] Unit tests cover over-funded, exact, and under-funded inputs.
- [ ] The canary test "over-funded funding draft is neither changed nor rejected" is un-TODOed and passes.
