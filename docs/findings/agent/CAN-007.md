# CAN-007 — Unsolicited SPLICE_FINALIZED and VC_FINALIZED messages overwrite trusted channel state

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** in-progress  
**Packages:** `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-host@0.13.4
**Source:** `security audit OMN-NEW-001, verified against source at 8fa26907`

## Context

The SPLICE_FINALIZED handler takes payload.channel from the peer message and writes it straight into the channel store. The VC_FINALIZED handler does the same for payload.factory and payload.channel, and deletes a channel on vc-close. Neither handler checks that the sender is the expected counterparty, that a proposal or acceptance is outstanding for that id, that the payload carries valid signatures, or that any chain evidence supports it.

## Impact

Any connected peer can overwrite persisted channel or factory state with its own object, or make the host forget a channel. Exploitability depends on transport access control: peers are bound by their transport key from the DHT and there is no allowlist, so "connected" is the only bar. This is a source-level finding; no exploit was executed.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** A finalized message that does not match a locally recorded proposal/acceptance is rejected, and state is only written after signature and chain verification.

**Actual:** lifecycle.ts writes the peer-supplied object unconditionally: channelStore.set on SPLICE_FINALIZED, and factory/channel set plus channelStore.delete on VC_FINALIZED.

**Evidence:**

- fix proposed in PR #218 (peer-guards.assertSpliceFinalized / assertVcFinalized); 19 guard tests
- packages/omnia-host/src/lifecycle.ts:365 — if (msg.type === "SPLICE_FINALIZED" && payload.channel) channelStore.set(...)
- packages/omnia-host/src/lifecycle.ts:588 — VC_FINALIZED: factories.set(payload.factory) and channelStore.set/delete(payload.channel)
- no lookup of spliceAcceptances/vcReplies before either write

## Where to fix

- `packages/omnia-host/src/lifecycle.ts`

### Approach

Treat a finalized message as a claim, not a fact. Require an outstanding local record keyed by spliceId or vcId, verify the finalized payload against that proposal (parties, balances, sequence, successor coin) and verify the counterparty signatures, then persist. Reject unsolicited ids instead of applying them.

## Constraints (do not violate)

- Do not trust any object supplied by the peer as authoritative state.
- Do not break the legitimate finalize path after a local acceptance.
- Keep emitting the existing observation events on success.

## Acceptance criteria

- [ ] A SPLICE_FINALIZED with no matching local acceptance is rejected and changes nothing.
- [ ] A VC_FINALIZED cannot delete a channel that has no outstanding close acceptance.
- [ ] A legitimate finalize still persists and becomes active.
