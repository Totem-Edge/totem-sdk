# OMN-002 — mintVtxo replaces the pool commitment root with a single-leaf tree

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-vtxo`
**Observed versions:** @totemsdk/omnia-vtxo@0.8.1
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-002`

## Context

mintVtxo builds its proof set from `[vtxo]` and assigns that single-leaf root to `pool.commitmentRoot`. The pool type holds no membership set and the mint does not advance epoch or batchId, so a second mint replaces the root and the first VTXO no longer verifies against the pool.

## Impact

Previously minted claims stop verifying against the pool root. Any verifier that anchors on the current root rejects legitimate holders; there is no epoch history to fall back to.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-vtxo test
```

**Expected:** After minting A then B, A and B both verify against the pool root the operator publishes.

**Actual:** pool.commitmentRoot equals the root of B alone; A's proof points at the earlier root.

**Evidence:**

- packages/omnia-vtxo/src/vtxo.ts: mintVtxo `buildVtxoProofSet([vtxo])`
- packages/omnia-vtxo/src/types.ts: OmniaVtxoPool has commitmentRoot but no membership set

## Where to fix

- `packages/omnia-vtxo/src/vtxo.ts`
- `packages/omnia-vtxo/src/pool.ts`
- `packages/omnia-vtxo/src/epoch-authority.ts`

### Approach

Decide the contract first: either commitmentRoot covers the whole active set (the pool carries the member leaves and mint rebuilds the tree) or it covers one epoch (mint advances epoch/batchId and the epoch journal is the authority for historical proofs). Implement the chosen contract atomically and record it in docs.

## Constraints (do not violate)

- Do not silently keep the single-leaf root — it makes the field mean something different from its name.
- Existing VTXO ids and leaves must not change.
- Epoch roots must remain verifiable after later mints.

## Acceptance criteria

- [ ] Two sequential mints leave both proofs verifiable against the published root.
- [ ] The pool type can represent the membership set or explicitly states per-epoch scope.
- [ ] A regression test mints N VTXOs and verifies all N.
