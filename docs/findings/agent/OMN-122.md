# OMN-122 — The Axia lease adapter does not defensively validate remote indices

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/wots-lease`
**Observed versions:** @totemsdk/wots-lease@1.0.3
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-120
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-120 (wots-lease/src/omnia-axia.ts:117-158)`

## Context

The adapter defaults missing returned indices to zero and checks the watermark with the supplied logical tree id, without establishing a local atomic reservation over the cryptographic key domain before returning the lease.

## Impact

An incomplete or conflicting remote response can be used as a lease, risking WOTS leaf reuse if the remote guarantee does not hold.

## Reproduce

```bash
pnpm --filter @totemsdk/wots-lease test
```

**Expected:** Incomplete or conflicting lease responses are rejected locally.

**Actual:** Missing indices default to zero.

**Evidence:**

- omnia-axia.ts:117-158

## Where to fix


### Approach

Reject responses missing any index, verify they advance the local watermark, and record a local reservation.

## Constraints (do not violate)

- Fail closed on a partial lease.
- Keep the remote contract as documented.

## Acceptance criteria

- [ ] A response without indices fails.
- [ ] A conflicting lease fails.
- [ ] A local reservation exists before use.
