# OMN-022 — The host signs peer-supplied virtual-channel plans without rebuilding them

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia-factory`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/omnia-vtxo@0.9.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia host signing audit, 2026-11-18 (verified against 997b7f40)`

## Context

VC_PROPOSAL passes payload.plan directly to signVirtualChannelOpen/signVirtualChannelClose. Those functions check that the local signer is a factory participant and sign plan.commitment, but never rebuild the plan from the factory allocations/channel state. omnia-factory/src/coordination.ts already rebuilds with buildVirtualChannelOpen, compares commitments and applies an approval policy; the production host bypasses that path.

## Impact

A peer can obtain a WOTS signature over a virtual-channel commitment chosen by the peer, without proving it is an authorised transition of the factory this host holds. The host also commits the lease reservation immediately.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** The host rebuilds the VC plan from local factory state, rejects a mismatched commitment, and signs only the locally derived commitment after approval.

**Actual:** lifecycle.ts passes payload.plan straight to signVirtualChannelOpen/Close; only signer membership is checked.

**Evidence:**

- packages/omnia-host/src/lifecycle.ts VC_PROPOSAL handler
- packages/omnia-factory/src/virtual.ts signVirtualChannelOpen (membership + sign plan.commitment)
- packages/omnia-factory/src/coordination.ts handleVcProposal (rebuild + compare + approval)

## Where to fix

- `packages/omnia-host/src/lifecycle.ts`
- `packages/omnia-factory/src/virtual.ts`

### Approach

Rebuild VC-open/close locally from the factory and channel state, compare commitments and ids, require an explicit approval decision, then sign the locally derived plan. Persist the approval and reservation so a retry cannot change the transaction.

## Constraints (do not violate)

- Never sign a commitment that only exists in the peer payload.
- Bind factoryId, vcId, parties and amounts to local state.
- Persist the approved plan before committing the lease.

## Acceptance criteria

- [ ] A mismatched VC commitment is rejected before any leaf is reserved.
- [ ] Signing uses the locally rebuilt plan.
- [ ] Repeated proposals reuse the same approval/result.
