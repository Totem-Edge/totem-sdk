# OMN-040 — A replayed opening proposal could overwrite an established channel

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/tx-builder@0.7.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia host audit, 2026-11-18 (verified against 51aed956)`

## Context

_handleChannelProposal always wrote the reconstructed channel with no existing-channel check, so a counterparty could reset an evolved channel to sequence zero with a different opening split. It now treats an existing channel as authoritative: an exact duplicate (same parties, funding coin/script, token and opening allocation) is an idempotent ACK, and changed opening terms are rejected.

## Impact

A counterparty could discard the latest jointly signed state and substitute a different opening allocation.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia test
```

**Expected:** An existing channel is never replaced by a CHANNEL_PROPOSAL.

**Actual:** Fixed: changed opening terms are rejected; identical replays do not overwrite.

**Evidence:**

- packages/omnia/src/integration.ts _handleChannelProposal
- packages/omnia/src/channel.ts openingBalances

## Where to fix

- `packages/omnia/src/integration.ts`
- `packages/omnia/src/channel.ts`
- `packages/omnia/src/types.ts`

### Approach

Persist the immutable opening allocation and make CHANNEL_PROPOSAL idempotent only for an exact duplicate; all balance changes must use state updates or splice.

## Constraints (do not violate)

- Never reset sequence, latestState or balances from an opening proposal.

## Acceptance criteria

- [ ] A changed allocation is rejected.
- [ ] An identical replay ACKs without overwriting.
- [ ] The stored channel object is unchanged.
