# OMN-075 — The pending splice journal does not record its expected successor

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-splice`
**Observed versions:** @totemsdk/omnia-splice@0.3.5
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-073`

## Context

PendingSpliceRecord has an `expected` field carrying the successor address, token and amount, and recoverInterruptedSplices() prefers it. finalizeSplice() writes its recovery record without populating it, so recovery falls back to the globally supplied observation parameters.

## Impact

When more than one splice is interrupted, recovery can reconcile one splice against another splice's expected successor — accepting a coin with the right shape but the wrong channel. The journal that exists to make recovery specific is not used in practice.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-splice test
```

**Expected:** Every production journal entry names the successor it expects.

**Actual:** The record written at broadcast time has no `expected` field, and recoverInterruptedSplices falls through to the caller-supplied address/token/amount.

**Evidence:**

- packages/omnia-splice/src/finalize.ts:307-314 — record omits `expected`
- packages/omnia-splice/src/successor.ts:178-195 — record.expected preferred, else global options

## Where to fix

- `packages/omnia-splice/src/finalize.ts`

### Approach

Compute the expected successor descriptor from the splice terms at journal-write time and make the field mandatory in the type, so a store cannot persist a record without it.

## Constraints (do not violate)

- Recovery must never use a global observation for a record that has its own expectation.
- Store atomically with the tx hex and txpow id already written.

## Acceptance criteria

- [ ] The journal record written before broadcast contains the expected successor.
- [ ] Two interrupted splices recover against their own expectations.
- [ ] A legacy record without `expected` is rejected or migrated explicitly, not silently defaulted.
