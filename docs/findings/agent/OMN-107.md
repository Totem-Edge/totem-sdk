# OMN-107 — Epoch recovery reconstructs history without authenticating it

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/vtxo`
**Observed versions:** @totemsdk/vtxo@0.10.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-105
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-105 (vtxo/src/epoch-authority.ts:64-83)`

## Context

Recovery rebuilds spent inputs and the current root from journal entries by taking the highest epoch. It does not verify each epoch signature, reject conflicting roots at one epoch, enforce transition ordering or detect repeated input consumption.

## Impact

Structural recovery is relied on as financial recovery; a corrupted journal can restore a root the operator never signed.

## Reproduce

```bash
pnpm --filter @totemsdk/vtxo test
```

**Expected:** Replay verifies signatures, monotonic epochs, unique inputs and agreement with the anchored epoch.

**Actual:** Recovery trusts the highest recorded epoch.

**Evidence:**

- epoch-authority.ts:64-83 (recovery)

## Where to fix


### Approach

Authenticated deterministic replay with monotonic validation and reconciliation against the externally anchored epoch.

## Constraints (do not violate)

- Fail closed on a signature that does not verify.
- Reject conflicting roots at the same epoch.

## Acceptance criteria

- [ ] A tampered journal entry cannot restore state.
- [ ] Recovery matches the anchored epoch.
