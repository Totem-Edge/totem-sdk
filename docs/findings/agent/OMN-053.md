# OMN-053 — The splice finalizer constructed a noncanonical witness without spending proofs

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-splice`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

assembleSpliceWitness used bespoke 4-byte counts and wrote zero coin/script proofs, unlike serializeOmniaWitness. The finalizer now uses the shared encoder in MULTISIG key order and refuses to broadcast without proofs for every spending input.

## Impact

A broadcast splice could carry a witness the node cannot validate.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-splice test
```

**Expected:** The witness matches the canonical serializer and carries proofs.

**Actual:** Fixed: canonical witness with mandatory proofs before broadcast.

**Evidence:**

- packages/omnia-splice/src/finalize.ts assembleSpliceWitness
- packages/omnia/src/witness.ts serializeOmniaWitness

## Where to fix

- `packages/omnia-splice/src/finalize.ts`

### Approach

Use the canonical witness encoder and require proof material to broadcast.

## Constraints (do not violate)

- Witness signatures follow MULTISIG key order.

## Acceptance criteria

- [ ] Broadcast without proofs is rejected.
- [ ] A proof-backed splice broadcasts.
