# OMN-078 — An observability failure can strand a committed operation or misreport it as failed

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-host@0.15.1
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-076`

## Context

withOperation() emits operation.executing outside the protected block, so a rejecting observer leaves the operation in `executing` with nothing to drive it forward. Inside the try it records `committed` and then awaits operation.committed; if that emit rejects, the catch attempts executing→failed on a record that is already `committed`, which throws an invalid-transition error.

## Impact

Observer failure is observers' business, but here it changes the financial lifecycle: an operation that committed can be reported as failed and become unreplayable, and an operation can stall in `executing` before any work started.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Observability delivery cannot change the authoritative operation state; a rejecting observer is recorded and the operation still commits or fails on its own merits.

**Actual:** With an observer that throws on operation.committed, the RPC rejects even though run() succeeded and the record is `committed`; with one that throws on operation.executing, the record stays `executing`.

**Evidence:**

- packages/omnia-host/src/api/methods.ts:546-551 — emit outside the try
- packages/omnia-host/src/api/methods.ts:553-558 — committed transition then await emit
- packages/omnia-host/src/api/methods.ts:560-566 — catch assumes status is executing

## Where to fix

- `packages/omnia-host/src/api/methods.ts`
- `packages/omnia-host/src/observe`

### Approach

Route all observer delivery through a non-throwing boundary (or a transactional outbox) so a failed emit is recorded and retried without affecting the state machine. Move the executing emit inside a protected block and never transition committed→failed.

## Constraints (do not violate)

- Observer failure must not be able to change or roll back an authoritative transition.
- Do not swallow observer errors silently: surface them on the observability channel.
- Keep the committed result readable even when the emit failed.

## Acceptance criteria

- [ ] A throwing observer cannot make a committed operation report failure.
- [ ] A throwing observer cannot leave an operation stuck in `executing` before run().
- [ ] Observer failures appear as their own recorded health signal.
