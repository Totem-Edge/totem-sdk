# OMN-071 — Quote validation establishes shape, not authenticity

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-lsp`
**Observed versions:** @totemsdk/omnia-lsp@0.1.0
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-069`

## Context

validateOpenQuote() requires only that signature is a non-empty string and that termsHash is 32 bytes. Neither is recomputed or verified. quoteMatchesManifest() compares provider identity, settlement address and token offering, and states in its own doc comment that it is not a substitute for manifest verification. The package exposes no API that verifies a quote's signature or its terms commitment.

## Impact

Every consumer of the LSP layer inherits an authenticity gap: a structurally valid quote cannot be distinguished from a forged one. This is the missing primitive that OMN-066 needs to close its authorization boundary.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-lsp test
```

**Expected:** A canonical verifyOpenQuote(quote, manifest, { now }) recomputes termsHash from the quoted fields, verifies the provider signature over it with the manifest identity key, and checks freshness.

**Actual:** A quote with signature 'not-a-signature' and an arbitrary termsHash passes validateOpenQuote() and quoteMatchesManifest().

**Evidence:**

- packages/omnia-lsp/src/quote.ts:114 — signature must be a non-empty string
- packages/omnia-lsp/src/quote.ts:152-170 — quoteMatchesManifest compares identity fields only
- no verifyOpenQuote export exists in packages/omnia-lsp/src/index.ts

## Where to fix

- `packages/omnia-lsp/src/quote.ts`
- `packages/omnia-lsp/src/index.ts`

### Approach

Add verifyOpenQuote(quote, manifest, options) that rebuilds the canonical terms object, recomputes the hash with the same domain separator used at issue time, verifies the signature through an injected verifier, and returns structured errors. Keep structural validation separate and name it as such.

## Constraints (do not violate)

- The canonical terms serialisation must be byte-identical to createUnsignedOpenQuote.
- Signature verification stays runtime-neutral via injection, matching signOpenQuote.
- Do not make validateOpenQuote imply authenticity in its name or docs.

## Acceptance criteria

- [ ] A mutated amount, fee, token, expiry or consumer identity is detected by the recomputed terms hash.
- [ ] A signature from a key other than the manifest identity key is rejected.
- [ ] A verifier that throws produces a structured failure, not an exception.
- [ ] Round-tripping a provider-issued quote verifies.
