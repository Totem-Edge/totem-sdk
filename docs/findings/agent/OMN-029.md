# OMN-029 — VTXO transfer verification omits value and recipient binding

**Kind:** sdk-defect  
**Severity:** medium  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-vtxo`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/omnia-vtxo@0.9.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia host signing audit, 2026-11-18 (verified against 997b7f40)`

## Context

verifyVtxoTransfer now requires a positive amount, binds from/to to the input/output owners, requires output.amount === transfer.amount, checks pool/token on the transfer record, and requires change with exact conservation for partial transfers.

## Impact

A standalone transfer record can no longer verify while describing a different recipient, amount or pool than the supplied output.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-vtxo test
```

**Expected:** Mismatched owner/amount/pool/token or a partial transfer without change is rejected.

**Actual:** Fixed in verifyVtxoTransfer.

**Evidence:**

- packages/omnia-vtxo/src/verify.ts verifyVtxoTransfer

## Where to fix

- `packages/omnia-vtxo/src/verify.ts`

### Approach

Enforce exact amount and owner binding, positive values, token/pool binding and conservation with change, while keeping the authoritative double-spend/operator-signature checks separate.

## Constraints (do not violate)

- Do not conflate this helper with the authoritative operator check.

## Acceptance criteria

- [ ] Wrong owner/amount/pool is rejected.
- [ ] Partial transfer requires change and conserves value.
