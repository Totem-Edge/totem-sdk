# OMN-125 — Fee earn-proofs can be appended more than once

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-pool`, `@totemsdk/liquidity-bond`
**Observed versions:** @totemsdk/omnia-pool@0.7.0, @totemsdk/liquidity-bond@0.4.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-123; fixed by keying fee records on the canonical earn-proof digest: the registry refuses the same evidence for the same position and source a second time, while distinct evidence and non-earnable adjustments still record
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-123 (omnia-pool/src/fees.ts:41-77, liquidity-bond/src/registry.ts:98-106)`

## Context

recordPoolFee verifies earn-proof evidence and appends a fee record; the registry appends without enforcing uniqueness of the evidence. The payout side has replay controls, the earning side does not.

## Impact

Repeated submission of the same valid evidence inflates recorded earned fees.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-pool test
```

**Expected:** Evidence is consumed exactly once.

**Actual:** Append-only with no evidence key.

**Evidence:**

- fees.ts:41-77
- registry.ts:98-106

## Where to fix


### Approach

Key fee records by evidence digest and reject a duplicate.

## Constraints (do not violate)

- Do not change the fee record shape without versioning.
- Keep legitimate multiple fees per hop distinct.

## Acceptance criteria

- [ ] The same evidence twice records one fee.
- [ ] Distinct evidence still records.

## Tests that prove it

- `tests/unit/liquidity-bond/src/__tests__/fees.test.ts`
