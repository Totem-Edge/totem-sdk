# OMN-063 — Funding activation did not consistently wait for chain confirmations

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia`, `@totemsdk/omnia-factory`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

The receiver checked confirmation depth, but the initiator marked a channel active on mere observation and the factory finalizer committed immediately after submission. Both now require depth; a channel or factory whose funding is not confirmed stays opening.

## Impact

Operational channels or factories could rest on unconfirmed funding.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia test
```

**Expected:** Activation requires the funding coin at depth.

**Actual:** Fixed: both paths gate on confirmations (default 1).

**Evidence:**

- packages/omnia/src/channel.ts finalizeChannelOpening
- packages/omnia-factory/src/factory.ts finalizeFactoryOpening

## Where to fix

- `packages/omnia/src/channel.ts`
- `packages/omnia-factory/src/factory.ts`

### Approach

Apply one finality rule: submitted → observed → confirmed → active.

## Constraints (do not violate)

- Submission is not confirmation.

## Acceptance criteria

- [ ] Shallow funding stays opening.
- [ ] Deep funding activates.
