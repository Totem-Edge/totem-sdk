# OMN-083 — Router fee proofs hash descriptive fields and are not settlement evidence

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-router`, `@totemsdk/omnia-pool`
**Observed versions:** @totemsdk/omnia-router@0.5.0
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-081`

## Context

buildRouterFeeProof() builds a canonical JSON hash over channelId, htlcId, recipient, amount, tokenId and settledAt, and nothing else. The hash proves the supplied data is internally consistent; it carries no authentication from either channel party and no reference to the state transition that actually paid the intermediary.

## Impact

Any downstream accounting that treats proofHash as evidence of earned routing income is unsound: the record can be produced for a payment that never settled. recordPoolFee consumes this structure, so pool income accounting inherits the weakness.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-router test
```

**Expected:** A fee proof binds the authenticated predecessor and successor channel states, both parties' authorization and the net amount the intermediary retained.

**Actual:** The proof is a self-consistent hash of caller-supplied fields; it verifies for an HTLC that was never fulfilled.

**Evidence:**

- packages/omnia-router/src/execute.ts:249-266 — proof fields and hash
- packages/omnia-router/src/execute.ts:268-274 — computeRouterFeeProofHash over canonicalJson
- packages/omnia-pool/src — recordPoolFee consumes the proof

## Where to fix

- `packages/omnia-router/src/execute.ts`
- `packages/omnia-pool/src`

### Approach

Attach the signed state transition (predecessor and successor state hashes, both signatures) and the fee actually retained, and verify both when the proof is consumed. Keep the current hash as an integrity check of the envelope, not as the evidence.

## Constraints (do not violate)

- Do not describe an unauthenticated hash as a settlement proof in API names or docs.
- Fee accounting must refuse a proof without verified bilateral authorization.
- Keep backwards compatibility explicit: version the proof.

## Acceptance criteria

- [ ] A proof for an unfulfilled HTLC fails verification.
- [ ] A proof with one party's signature missing fails verification.
- [ ] Pool fee accounting refuses an unverified proof.
- [ ] The retained fee is derived from the state delta, not asserted.
