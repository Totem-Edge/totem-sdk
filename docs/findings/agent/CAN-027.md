# CAN-027 — omnia-vtxo has no dedicated lifecycle scenario

**Kind:** canary-coverage  
**Severity:** medium  
**Status:** open  
**Packages:** `@totemsdk/omnia-vtxo`
**Observed versions:** @totemsdk/omnia-vtxo@0.9.0
**Source:** `docs/coverage-gap-report.md:157, re-confirmed 25 Nov 2026`

## Context

The coverage-gap report already recorded that omnia-vtxo has no dedicated scenario and proposed one (originally numbered 43, now omnia-observe). The only exercise is incidental: 39-custody-escape-exec runs the pool owner path, and 24-omnia-pool-001-rehearsal touches pool accounting. Mint, claim, transfer, refresh and exit are never driven end to end. The audit of 25 November 2026 raised three findings against the exit path (OMN-087, OMN-088, OMN-089) that a lifecycle scenario would have surfaced.

## Impact

VTXO-backed liquidity — a Pool 001 capability — has no live evidence. Exit-entitlement binding, single-exit enforcement and completion finality can regress without any gate noticing.

## Reproduce

```bash
cd artifacts/canary && pnpm run canary list | grep -i vtxo
```

**Expected:** A scenario drives mint → claim → transfer → refresh → exit with balance conservation at each step.

**Actual:** No scenario covers the VTXO lifecycle; the only vtxo references are the pool-owner leg of 39-custody-escape-exec and the pool rehearsal.

**Evidence:**

- docs/coverage-gap-report.md:157 — "omnia-vtxo (virtual channels) has no dedicated scenario"
- packages/omnia-vtxo/src/exit.ts has no canary caller

## Where to fix

- `artifacts/canary/src/scenarios/51-omnia-vtxo-claim.ts`
- `artifacts/canary/src/orchestrator/ScenarioRegistry.ts`
- `artifacts/canary/src/config/profiles.ts`

### Approach

Add a local-simulated VTXO lifecycle scenario: mint into a pool, claim, transfer to a second owner, refresh across an epoch, then exit — asserting root/epoch continuity, receipt consumption, and balance conservation at every transition. Include the negative legs for OMN-087 (wrong epoch root) and OMN-088 (second exit draft).

## Constraints (do not violate)

- Do not reuse the pool-rehearsal fixtures if they bypass the VTXO state machine.
- Assert receipt consumption rather than trusting exitConsumedAt to have been set by the caller.
- Keep the exit leg simulated unless a chain provider is supplied.

## Acceptance criteria

- [ ] Mint, claim, transfer, refresh and exit each have an assertion.
- [ ] A second exit draft for the same VTXO is refused.
- [ ] An entitlement against a mismatched epoch root is refused.
- [ ] Pool roots and epochs are continuous across the refresh.
