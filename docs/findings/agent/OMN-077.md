# OMN-077 — Operation replay verification loses its receiver and throws instead of returning the committed result

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-host@0.15.1
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-075`

## Context

withOperation() reads verifyRequest off the operation store into a local variable and calls it as a bare function. OperationStore.verifyRequest() calls this.get(), so the call throws TypeError. Any RPC retried with an existing operationId therefore fails instead of returning the previously committed result. The unit tests missed it because they stub the store with an object literal whose verifyRequest is a closure.

## Impact

The host's idempotency guarantee does not hold for the real SQLite-backed store: a client that retries after a timeout gets an error rather than the committed result, and cannot tell whether the operation ran. Only the operationId path is affected.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** A retried operation with an identical request returns the stored result.

**Actual:** On the real OperationStore the retry throws TypeError: Cannot read properties of undefined (reading 'get').

**Evidence:**

- packages/omnia-host/src/api/methods.ts:514-516 — method extracted and invoked unbound
- packages/omnia-host/src/stores/operations.ts:119-122 — verifyRequest uses this.get()
- packages/omnia-host/src/lifecycle.ts:236 — production constructs a real OperationStore
- tests/unit/omnia-host/src/__tests__/mutations.test.ts:233 — mock uses a closure, so it cannot catch this

## Where to fix

- `packages/omnia-host/src/api/methods.ts`
- `tests/unit/omnia-host/src/__tests__`

### Approach

Call the method on the store (or bind it). Add a regression test that replays an operation through a real OperationStore on a temp sqlite file, not a stubbed object.

## Constraints (do not violate)

- Do not change OperationStore's contract to accommodate an unbound call.
- Keep the conflict error for a genuinely different request.
- The regression test must not mock the store.

## Acceptance criteria

- [ ] Replaying a committed operation through the real store returns its result.
- [ ] Replaying with different params still raises OperationConflictError.
- [ ] A test exercises the real store and would fail against the unbound call.
