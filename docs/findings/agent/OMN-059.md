# OMN-059 — A unilateral VTXO exit could alter the remaining pool root and epoch

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-vtxo`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

The individual-exit branch returned before asserting the successor commitment root or epoch, so an exit could leave a residual pool whose membership matched no published state. Both ports are now preserved in every holder exit branch.

## Impact

Holders could lose proof continuity after another holder exited.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-vtxo test
```

**Expected:** An individual exit preserves STATE(100) and STATE(101).

**Actual:** Fixed: the exit branch asserts both are unchanged.

**Evidence:**

- packages/omnia-vtxo/src/pool-script.ts buildPoolScript

## Where to fix

- `packages/omnia-vtxo/src/pool-script.ts`

### Approach

Assert root and epoch preservation inside the exit branch, before any RETURN.

## Constraints (do not violate)
