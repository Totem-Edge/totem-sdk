# OMN-057 — Channel capacity warnings ignore the host shared physical WOTS tree

**Kind:** sdk-defect  
**Severity:** medium  
**Status:** open  
**Packages:** `@totemsdk/omnia`, `@totemsdk/omnia-host`, `@totemsdk/wots-lease`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/wots-lease@0.5.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

enforceUpdateGuards estimates consumption as newSequence * 2 for the channel alone. The host maps every logical tree label onto one physical tree, so many healthy-looking channels can exhaust the shared 4,096-leaf budget together with factory and receipt signing.

## Impact

Availability and capacity planning: true exhaustion is still refused by the lease provider, so this is not key reuse.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia test
```

**Expected:** Capacity warnings derive from the physical lease provider's consumed/reserved leaves.

**Actual:** Warnings are computed per channel from the sequence number only.

**Evidence:**

- packages/omnia/src/guards.ts enforceUpdateGuards
- packages/omnia/src/capacity.ts assessCapacity
- packages/omnia-host/src/signing.ts lease mapping

## Where to fix

- `packages/omnia/src/guards.ts`
- `packages/omnia/src/capacity.ts`
- `packages/omnia-host/src/signing.ts`

### Approach

Feed actual lease usage into the capacity decision and budget per existing channel plus recovery requirements.

## Constraints (do not violate)

- Keep failing closed on true exhaustion.
- Do not weaken the per-channel double-sign guard.

## Acceptance criteria

- [ ] A host nearing physical exhaustion warns before signing.
- [ ] A single channel cannot mask shared-tree pressure.
