# OMN-111 — One accepted commitment can create multiple liquidity positions

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-pool`, `@totemsdk/liquidity-bond`
**Observed versions:** @totemsdk/omnia-pool@0.7.0, @totemsdk/liquidity-bond@0.4.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-109; fixed by keying positions on commitmentId: createPositionFromCommitment returns the existing position on retry and the registry refuses a second position for one commitment
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-109 (omnia-pool/src/deposit.ts:152-183, liquidity-bond/src/position.ts:9-46)`

## Context

createPositionFromCommitment mints a new position id on every call and does not check the registry for an existing position derived from the same commitment. The registry prevents one funding coin backing several commitments, but not one commitment backing several positions.

## Impact

Recorded liabilities can exceed real backing capital by a multiple of the number of retries.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-pool test
```

**Expected:** A commitment produces exactly one position; a retry returns the existing one.

**Actual:** Each call creates a new position id.

**Evidence:**

- deposit.ts:152-183
- position.ts:9-46

## Where to fix


### Approach

Make commitmentId a unique key for position creation and return the existing position on retry.

## Constraints (do not violate)

- Do not allow two positions per commitment.
- Keep partial withdrawal receipts separate from positions.

## Acceptance criteria

- [ ] Replaying an accepted deposit returns the original position.
- [ ] The registry rejects a second position for one commitment.

## Tests that prove it

- `tests/unit/omnia-pool/src/__tests__/pool.test.ts`
