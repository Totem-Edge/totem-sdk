# OMN-061 — The default co-signer could authorize HTLC fulfilment without a preimage

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

validateHtlcSet only compared terms while both versions stayed pending, so a peer could mark an HTLC fulfilled and credit itself while keeping the id. A pending → fulfilled transition now requires a matching preimage, and pending → timed_out requires an authoritative chain height.

## Impact

A conditional payment could be released without satisfying its hashlock.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia test
```

**Expected:** Terminal HTLC transitions require proof.

**Actual:** Fixed: preimage/hashlock and chain-height evidence are mandatory.

**Evidence:**

- packages/omnia/src/sign.ts validateHtlcSet
- packages/omnia/src/integration.ts _handleStateUpdate

## Where to fix

- `packages/omnia/src/sign.ts`
- `packages/omnia/src/types.ts`
- `packages/omnia/src/integration.ts`

### Approach

Validate terminal transitions against the stored record plus the revealed preimage or chain height.

## Constraints (do not violate)

- Never sign a fulfilment without a verified preimage.

## Acceptance criteria

- [ ] Fulfilment without a preimage is rejected.
- [ ] A wrong preimage is rejected.
- [ ] Timeouts need height.
