# OMN-037 — Factory RPCs interpret contributions as atoms instead of decimal amounts

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia-factory`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/tx-builder@0.7.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia host audit, 2026-11-18 (verified against 51aed956)`

## Context

prepareFactory and createFactory used BigInt(requiredString(item, "contributionAmount")), unlike every other host monetary parameter. A decimal fraction was rejected and a whole number meant that many atoms. Both handlers now use rpcAmountToAtoms.

## Impact

Fractional contributions were rejected and whole numbers were treated as atoms, corrupting totalValue, allocations and escape shares.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** A 0.2 MINIMA contribution is accepted as 0.2 MINIMA.

**Actual:** Fixed: both factory paths convert at the RPC boundary.

**Evidence:**

- packages/omnia-host/src/api/methods.ts prepareFactory/createFactory contribution parsing

## Where to fix

- `packages/omnia-host/src/api/methods.ts`

### Approach

Convert every participant contribution with rpcAmountToAtoms and cover both the prepared and one-shot factory paths.

## Constraints (do not violate)

- Do not mix atom and decimal contribution paths.

## Acceptance criteria

- [ ] Fractional contributions produce atom allocations.
- [ ] Oversized atom integers are rejected.
