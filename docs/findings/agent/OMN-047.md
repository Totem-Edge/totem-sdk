# OMN-047 — Operator receipt signing broke after the first mint into a VTXO pool

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-vtxo`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

Mint roots commit every accumulated pool member, but the receipt payload was verified against a root rebuilt from only the receipt outputs, so the second mint could not be co-signed. Receipts now verify outputs against the pool member set and the pool root.

## Impact

Issuance and operator authorization diverged after the first mint.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-vtxo test
```

**Expected:** The second mint in a pool prepares a valid receipt.

**Actual:** Fixed: batch verification accepts the authoritative member set.

**Evidence:**

- packages/omnia-vtxo/src/receipt.ts buildVtxoReceiptPayload
- packages/omnia-host/src/api/methods.ts prepareVtxoReceipt

## Where to fix

- `packages/omnia-vtxo/src/receipt.ts`
- `packages/omnia-host/src/api/methods.ts`

### Approach

Verify receipt outputs against the pool member leaves and the pool root; the host passes its authoritative set.

## Constraints (do not violate)

- A receipt must never be verified against a root it supplied itself.

## Acceptance criteria

- [ ] Second and later mints co-sign.
- [ ] An output outside the member set is rejected.

## Tests that prove it
