# OMN-067 — Admission validates the consumer contribution only, then the host swaps the two sides

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-lsp-provider`
**Observed versions:** @totemsdk/omnia-lsp-provider@0.1.0
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-065`

## Context

evaluateOpenRequest() checks minChannel, maxChannel and direction capacity against request.localAmount alone. request.remoteAmount — the provider's own capital commitment — is never compared with the asset limits or available funds. The host adapter then maps quote.remoteAmount to the host's localAmount, so the unvalidated field becomes the provider's actual funding amount.

## Impact

The provider's real capital commitment is not constrained by the advertised channel limits or capacity policy. A consumer-supplied remoteAmount is the amount the provider funds, so the manifest's maxChannel is bypassable and the provider's exposure is set by its counterparty.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-lsp-provider test
```

**Expected:** Admission validates both contributions independently, and the total channel value, available provider funds and directional liquidity against the manifest.

**Actual:** Only localAmount is range- and capacity-checked; remoteAmount is unconstrained and is passed to totem_omniaOpenChannel as localAmount (the provider side).

**Evidence:**

- packages/omnia-lsp-provider/src/policy.ts:86-99 — every limit compares request.localAmount
- packages/omnia-lsp-provider/src/host.ts:91-92 — localAmount: quote.remoteAmount, remoteAmount: quote.localAmount

## Where to fix

- `packages/omnia-lsp-provider/src/policy.ts`
- `packages/omnia-lsp-provider/src/host.ts`
- `packages/omnia-lsp-provider/src/quote.ts`

### Approach

Validate both sides: each contribution against minChannel/maxChannel, the sum against total capacity, the provider side against the asset's outbound/inbound capacity for the requested direction, and against a provider-supplied available-funds bound. Quote both amounts explicitly so the consumer sees what it is asking the provider to commit.

## Constraints (do not violate)

- Do not keep the manifest's limits meaningful for one side only.
- Keep the consumer's perspective in the wire quote; perform the swap once, at the host boundary.
- Do not infer provider capacity from the host's coin selection.

## Acceptance criteria

- [ ] A request whose remoteAmount exceeds maxChannel or provider capacity is refused.
- [ ] Total channel value is bounded independently of how it is split.
- [ ] The provider-side amount the host funds equals the amount admission approved.
- [ ] Directional capacity is checked against the side that actually supplies it.
