# OMN-055 — VTXO transfers and refreshes produced active claims absent from the pool commitment

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-vtxo`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

Minting appended to the pool member set, but transfer and refresh outputs kept single-batch proofs and were stored active without joining it. A pool transition primitive now consumes inputs and adds outputs at a new epoch, and the host applies it before persisting.

## Impact

Active VTXOs could fail membership verification and existing claims were not anchored.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-vtxo test
```

**Expected:** Transfer/refresh outputs are committed by the pool.

**Actual:** Fixed: transitionPoolMembers consumes inputs, adds outputs and republishes the root.

**Evidence:**

- packages/omnia-vtxo/src/pool.ts transitionPoolMembers
- packages/omnia-host/src/api/methods.ts transferVtxo/refreshVtxo

## Where to fix

- `packages/omnia-vtxo/src/pool.ts`
- `packages/omnia-host/src/api/methods.ts`

### Approach

Add an atomic membership transition and use it for transfer and refresh.

## Constraints (do not violate)

- A consumed id can never re-enter the set.
- Each transition publishes a new epoch root.

## Acceptance criteria

- [ ] Outputs verify against the pool.
- [ ] Consumed inputs leave the set.
- [ ] Receipts prepare after the transition.

## Tests that prove it
