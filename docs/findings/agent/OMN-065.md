# OMN-065 — Rust/WASM CHECKSIG cannot verify a tree signature (the on-chain form)

**Kind:** sdk-defect  
**Severity:** medium  
**Status:** open  
**Packages:** `@totemsdk/kissvm`, `@totemsdk/core-wasm`
**Observed versions:** @totemsdk/kissvm@1.4.1, @totemsdk/core-wasm@0.1.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `OMN-064 parity harness, 2026-11-18`

## Context

The TypeScript evaluator verifies a canonical tree signature with deserializeTreeSignature + verifyTreeSignature. The Rust/WASM evaluator only has the flat WOTS path: core-wasm exposes verify_tree_signature over a deserialized struct, but no byte reader for TreeSignature, so the wasm leg rejects the on-chain signature form. The parity suite records this as pending-tree-signature instead of hiding it.

## Impact

A covenant that verifies an oracle or recovery certificate works in the TypeScript evaluator and fails closed in the WASM evaluator. That is an availability/parity divergence, not a signature-forgery path.

## Reproduce

```bash
pnpm --filter @totemsdk/kissvm test
```

**Expected:** TS and WASM both verify a canonical tree signature over the supplied data.

**Actual:** TS passes; WASM returns false for the tree-signature fixtures.

**Evidence:**

- packages/kissvm/src/eval.ts evalChecksig
- packages/kissvm/rust/src/eval.rs CheckSig
- packages/core-wasm/src/treekey.rs (no TreeSignature byte reader)
- tests/unit/kissvm-parity/src/__tests__/checksig-parity.test.ts

## Where to fix

- `packages/core-wasm/src/treekey.rs`
- `packages/kissvm/rust/src/eval.rs`

### Approach

Add a MiniData byte reader for TreeSignature in core-wasm (matching Signature.convertMiniDataVersion), use it in the Rust CHECKSIG branch, rebuild both wasm targets, and promote the pending fixtures.

## Constraints (do not violate)

- Do not accept a flat signature where the node expects a tree signature.
- Keep TS and Rust byte-identical on the same fixtures.

## Acceptance criteria

- [ ] The tree-signature fixtures pass in TS and WASM.
- [ ] The parity suite has no pending-tree-signature entries.
- [ ] The node leg (scripts/kissvm-node-parity.mjs) agrees.
