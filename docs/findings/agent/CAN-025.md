# CAN-025 — Liquidity-bond passes an atom count as the verifier's decimal claimedAmount, rejecting every pool deposit

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/liquidity-bond`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/liquidity-bond@0.3.3, @totemsdk/omnia-host@0.14.0
**Source:** `omnia-host pool test against the real deposit path (`depositToPool` -> `verifyDeposit`)`

## Context

`VerifyDepositParams.claimedAmount` is decimal MINIMA text (chain-provider compares it with the node's decimal `coin.amount`). liquidity-bond built it from `commitment.amount.toString()`, and `commitment.amount` is an atom count, so the omnia-host verifier converted it to atoms a second time. A 100000 MINIMA deposit became 1e93 atoms at the comparison.

## Impact

Every non-zero liquidity-pool deposit failed the amount gate with "insufficient amount", and `acceptLiquidityCommitment`/`confirmLiquidityCommitment` refused to accept or confirm funding. The failure looked like a funding problem, not a unit bug.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** a commitment for a funded coin of 100000 MINIMA passes on-chain verification.

**Actual:** `insufficient amount`: coinAmountAtoms(coin) = 1e49 vs amountToAtoms("1" + 49 zeros) = 1e93.

**Evidence:**

- npx jest --config tests/jest/omnia-host.cjs --runInBand tests/unit/omnia-host/src/__tests__/pool.test.ts
- packages/liquidity-bond/src/commitment.ts:59,123,162 — `claimedAmount: commitment.amount.toString()`
- packages/liquidity-bond/src/types.ts:256 — `amount: bigint` (atoms)
- packages/chain-provider/src/types.ts:83 — `claimedAmount` is decimal text
- packages/omnia-host/src/api/methods.ts — verifier compares `coinAmountAtoms(coin)` with `amountToAtoms(request.claimedAmount)`

## Where to fix

- `packages/liquidity-bond/src/commitment.ts`

### Approach

Render the commitment amount as decimal text at the verifier boundary with `atomsToAmount(commitment.amount)`; keep the verifier contract decimal and the internal ledger in atoms.

## Constraints (do not violate)

- Do not change `VerifyDepositParams.claimedAmount` to atoms; it compares against the node's decimal `coin.amount`.
- Do not weaken the amount gate.
