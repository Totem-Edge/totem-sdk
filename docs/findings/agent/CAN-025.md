# CAN-025 — Liquidity-bond passes an atom count as the verifier's decimal claimedAmount, rejecting every pool deposit

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/liquidity-bond`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/liquidity-bond@0.3.2, @totemsdk/omnia-host@0.13.6
**Fixed in:** 9213dd32

## Context

`VerifyDepositParams.claimedAmount` is decimal MINIMA text: chain-provider
compares it with the node's decimal `coin.amount` (`compareAmounts`), and the
omnia-host verifier converts it once with `amountToAtoms`. liquidity-bond built
that field from `commitment.amount.toString()`, but `commitment.amount` is a
`bigint` atom count. The verifier therefore converted atoms to atoms, a second
factor of 10^44.

## Impact

Every non-zero pool deposit fails the amount gate with `insufficient amount`.
`acceptLiquidityCommitment` and `confirmLiquidityCommitment` refuse to accept or
confirm funding, so the pool lifecycle cannot start. The error presents as a
funding problem, not a unit problem.

## Reproduce

```bash
npx jest --config tests/jest/omnia-host.cjs --runInBand \
  tests/unit/omnia-host/src/__tests__/pool.test.ts
```

**Expected:** a commitment for a coin funded with 100000 MINIMA passes on-chain verification.

**Actual:** `insufficient amount` — `coinAmountAtoms(coin) = 1e49` versus
`amountToAtoms(claimedAmount) = 1e93`.

**Evidence:**

- `packages/liquidity-bond/src/commitment.ts:59,123,162` — `claimedAmount: commitment.amount.toString()`
- `packages/liquidity-bond/src/types.ts:256` — `amount: bigint` (atoms)
- `packages/chain-provider/src/types.ts:83` — `claimedAmount` is decimal text
- `packages/omnia-host/src/api/methods.ts` — pool verifier compares atom vs `amountToAtoms(claimedAmount)`

## Where to fix

- `packages/liquidity-bond/src/commitment.ts`

### Approach

Render the commitment amount as decimal text at the verifier boundary:
`atomsToAmount(commitment.amount)`. Keep the chain-provider contract decimal and
the internal ledger in atoms.

## Constraints (do not violate)

- Do not change `VerifyDepositParams.claimedAmount` to atoms; it is compared
  with the node's decimal `coin.amount`.
- Do not weaken the amount gate.

## Acceptance criteria

- [x] A 100000 MINIMA pool deposit verifies and is accepted.
- [x] An under-funded coin still fails.
- [x] The pool lifecycle test passes with its original assertions.
