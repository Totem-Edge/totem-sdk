# OMN-005 — recordPoolFee trusts a caller-supplied `verified` flag

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/omnia-pool`, `@totemsdk/liquidity-bond`
**Observed versions:** @totemsdk/omnia-pool@0.5.4, @totemsdk/liquidity-bond@0.3.2
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-005`

## Context

recordPoolFee forwards `params.verified` into recordLiquidityFee, where earnable records count toward LP entitlement only when `verified === true`. The verifier exists (`feeProofVerifier.verifyFeeProof`) but this path never calls it. claimFees and compoundFees likewise accept any `payoutRef` without confirming it is a settled payout.

## Impact

A caller trusted to record fees can manufacture verified earnings, or compound them into principal, without establishing that any fee was paid.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-pool test
```

**Expected:** An earnable fee record without a verifiable proof cannot increase unclaimed LP fees.

**Actual:** `verified: true` is accepted as-is and the record becomes earnable.

**Evidence:**

- packages/omnia-pool/src/fees.ts: recordPoolFee passes `verified: params.verified`
- packages/liquidity-bond/src/fees.ts: `.filter((r) => !isEarnableSource(r.source) || r.verified === true)`
- packages/liquidity-bond/src/fees.ts: the verifier is only used by the separate proof path

## Where to fix

- `packages/omnia-pool/src/fees.ts`
- `packages/liquidity-bond/src/fees.ts`

### Approach

Replace the boolean with a verification capability: recordPoolFee either receives a verifier and proof, or records the fee as unverified. Claims and compounds must consume a unique settled payout reference.

## Constraints (do not violate)

- No caller-controlled boolean may gate earnable accounting.
- Keep unverified records visible for audit but non-earnable.
- Reused payout references must be rejected, not ignored.

## Acceptance criteria

- [ ] A forged `verified` flag cannot increase unclaimed fees.
- [ ] A claim or compound with an unknown or reused payoutRef is rejected.
- [ ] The verified path still credits the LP.
