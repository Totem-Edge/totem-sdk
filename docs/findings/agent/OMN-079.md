# OMN-079 — An operation whose financial side effect is unknown is classified as a retryable failure

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-host@0.15.1
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-077`

## Context

withOperation() catches every exception from run() and moves the operation to `failed`, and the retry guard accepts `pending` and `failed`. There is no distinction between a failure before a financial side effect and a failure after signing, broadcasting or a remote party accepting. The store's status union already includes `unknown`, but nothing sets it.

## Impact

Retrying after an ambiguous failure can repeat a financial side effect. The host relies entirely on each handler being individually careful, which the register already shows is not the case (CAN-022, OMN-077).

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** A handler that cannot prove whether its side effect occurred leaves the operation in a reconciling state, and retry is refused until reconciliation says it did not happen.

**Actual:** Any exception yields status `failed`, which the retry guard accepts on the next call.

**Evidence:**

- packages/omnia-host/src/api/methods.ts:530-533 — failed is retryable
- packages/omnia-host/src/api/methods.ts:560-562 — every caught error becomes failed
- packages/omnia-host/src/stores/operations.ts:5 — `unknown` exists in OperationStatus but is never written

## Where to fix

- `packages/omnia-host/src/api/methods.ts`
- `packages/omnia-host/src/stores/operations.ts`

### Approach

Introduce an explicit unknown-outcome state. Handlers (or the RPC layer) declare the point after which an error is ambiguous; withOperation records `unknown` and refuses retry until a reconciliation step resolves it to committed or failed.

## Constraints (do not violate)

- Fail closed: ambiguity is not retried.
- Reconciliation must be able to consult the chain and the peer, not only local state.
- Do not let an `unknown` operation be silently re-executed by a client retry.

## Acceptance criteria

- [ ] A failure after broadcast/sign/remote-accept records `unknown`.
- [ ] A retry against `unknown` is refused with an actionable error.
- [ ] Reconciliation resolves `unknown` to committed or failed with evidence.
- [ ] A failure before any side effect remains plainly retryable.
