# CAN-011 — Both live splice paths omit chainProvider, so a broadcast splice is marked active with a placeholder coin

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia-splice`
**Observed versions:** @totemsdk/omnia-host@0.13.4, @totemsdk/omnia-splice@0.3.2
**Source:** `security audit OMN-NEW-005, verified against source at 8fa26907`

## Context

observeSpliceSuccessor exists precisely because the predecessor coin is spent and the successor must be found on chain. finalizeSplice only calls it when options.chainProvider is set; otherwise it defaults successorStatus to "active" and spliceFundingCoinId to `${txid}-0`, which is a placeholder. Both host call sites (prepared splice and direct splice) pass no chainProvider.

## Impact

A splice is treated as confirmed before its successor coin exists. The channel is reported active with a coin id that is not a real output, restart recovery has nothing valid to resume from, and later operations can act on a channel that the chain does not have.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** A spliced channel stays funding_pending until the successor coin is observed on chain.

**Actual:** Without chainProvider the branch is skipped and status is set to active immediately.

**Evidence:**

- fix proposed in PR #218 (finalizeSplice defaults to funding_pending; both call sites pass a chain observer)
- packages/omnia-host/src/api/methods.ts:1368 — finalizeSplice(..., { broadcast }) (no chainProvider)
- packages/omnia-host/src/api/methods.ts:3076 — finalizeSplice(..., { broadcast, proposerLeaseProvider })
- packages/omnia-splice/src/finalize.ts:345 — let successorStatus = "active"; only replaced inside if (options?.chainProvider)

## Where to fix

- `packages/omnia-host/src/api/methods.ts`
- `packages/omnia-splice/src/finalize.ts`

### Approach

Pass the host chain adapter at both call sites, and make the absence of a chainProvider an error rather than an implicit "assume active". Default to funding_pending when observation is unavailable.

## Constraints (do not violate)

- Do not use `${txid}-0` as a funding coin id for any state that can be acted on.
- Do not block the RPC indefinitely: observation stays bounded.

## Acceptance criteria

- [ ] Both call sites pass a chain provider.
- [ ] finalizeSplice without observation yields funding_pending, never active.
- [ ] A splice becomes active only after the successor is found with the required confirmations.
