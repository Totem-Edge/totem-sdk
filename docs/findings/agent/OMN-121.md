# OMN-121 — The signing policy is skipped when a request carries no amount

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia`
**Observed versions:** @totemsdk/omnia-host@0.16.0, @totemsdk/omnia@4.0.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-119; fixed on both sides: signState derives the signed amount from the largest balance move or the pending HTLC value and puts it in the sign context, and a policy with maxAmount refuses a request that carries no amount, a non-integer amount or a negative amount
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-119 (omnia-host/src/signer-port.ts:153-168, omnia/src/sign.ts:277-288)`

## Context

The policy signer applies its maximum-amount check only when request.context.amount is supplied. signState constructs chain-signing requests without an amount, so a configured spending limit does not apply to them.

## Impact

A spending policy can be bypassed by a signing path that omits the amount.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Policy inputs derive from the canonical transaction and the channel transition.

**Actual:** Amount is optional caller metadata.

**Evidence:**

- signer-port.ts:153-168
- sign.ts:277-288

## Where to fix


### Approach

Derive the amount from the transaction being signed and refuse when it cannot be determined.

## Constraints (do not violate)

- Do not make the limit optional.
- Keep non-financial signing paths working.

## Acceptance criteria

- [ ] A request without a derivable amount is refused under a spending policy.
- [ ] The limit uses the canonical amount.
