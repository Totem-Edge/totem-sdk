# OMN-035 — VTXO epochs are marked published after broadcast, not chain confirmation

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-vtxo`, `@totemsdk/chain-provider`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/chain-provider@0.4.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia host audit, 2026-11-18 (verified against 41106016 / 997b7f4)`

## Context

anchorBatch calls authority.markPublished(epoch) as soon as submission reports success. MinimaRpcProvider.submitTransaction reports mining/submission, not accepted-chain inclusion at depth, so the journal can record an epoch as published without confirmation and without reorg handling.

## Impact

Downstream consumers may treat a locally recorded root as chain-backed settlement evidence when the anchor was never confirmed.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-vtxo test
```

**Expected:** signed/submitted/included/confirmed/published are distinct and confirmation is checked on-chain.

**Actual:** published is set immediately after submitTransaction succeeds.

**Evidence:**

- packages/omnia-vtxo/src/anchor.ts anchorBatch
- packages/omnia-vtxo/src/epoch-authority.ts
- packages/chain-provider/src/providers/minima-rpc.ts submitTransaction

## Where to fix

- `packages/omnia-vtxo/src/anchor.ts`
- `packages/omnia-vtxo/src/epoch-authority.ts`

### Approach

Separate the publication states; confirm on-chain at the required depth before markPublished; reconcile/invalidate on reorg.

## Constraints (do not violate)

- Do not equate submission with confirmation.

## Acceptance criteria

- [ ] An unconfirmed/rejected/reorged anchor is not published.
- [ ] A confirmed anchor advances only after depth is verified.

## Tests that prove it
