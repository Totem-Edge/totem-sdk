# OMN-118 — VTXO conservation verification accepts duplicate and negative records

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/vtxo`
**Observed versions:** @totemsdk/vtxo@0.10.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-116
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-116 (vtxo/src/verify.ts:241-293)`

## Context

verifyConservation checks pool ids, token ids and aggregate amounts. It does not reject duplicate inputs, duplicate outputs or individually negative records.

## Impact

A crafted input set can pass conservation while double-counting or negating amounts.

## Reproduce

```bash
pnpm --filter @totemsdk/vtxo test
```

**Expected:** Duplicate ids and negative amounts are rejected centrally.

**Actual:** Only aggregates are compared.

**Evidence:**

- verify.ts:241-293

## Where to fix


### Approach

Add duplicate-id and non-negative checks to the shared verifier.

## Constraints (do not violate)

- Keep the strict/lte modes.
- Do not rely on per-caller guards.

## Acceptance criteria

- [ ] Duplicate inputs or outputs fail.
- [ ] A negative amount fails.
