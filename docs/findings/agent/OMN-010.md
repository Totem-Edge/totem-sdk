# OMN-010 — verifyVtxo accepts a VTXO with no membership proof and never anchors the root

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/omnia-vtxo`
**Observed versions:** @totemsdk/omnia-vtxo@0.8.1
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Depends on:** `OMN-002` — land those first.
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-010`

## Context

verifyVtxo only checks the proof when `proof.leaf` and `proof.root` are present, and verifyVtxoProof checks the tree against the root carried in the proof itself. Nothing compares that root to the pool's anchored root, and the function never receives the pool.

## Impact

A VTXO with no proof, or with a self-consistent proof against a root the operator never published, can be reported valid. Combined with OMN-002 there is no current root to anchor against.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-vtxo test
```

**Expected:** A VTXO whose proof root is not the anchored pool root is invalid.

**Actual:** The proof is skipped when absent; when present it is checked only against its own root.

**Evidence:**

- packages/omnia-vtxo/src/verify.ts: `if (vtxo.proof && vtxo.proof.leaf && vtxo.proof.root)`
- packages/omnia-vtxo/src/verify.ts: verifyVtxoProof uses `proof.root`

## Where to fix

- `packages/omnia-vtxo/src/verify.ts`

### Approach

Take the expected root as a required argument (or a pool/epoch record) and fail closed when the proof is missing or points elsewhere. Keep a separate structural check for offline inspection.

## Constraints (do not violate)

- Missing proof must be an error on the authoritative path, not a skipped check.
- Do not silently trust a root supplied by the artifact under test.

## Acceptance criteria

- [ ] A VTXO without a proof fails authoritative verification.
- [ ] A proof against a different root fails.
- [ ] A valid proof against the anchored root passes.
