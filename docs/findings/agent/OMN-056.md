# OMN-056 — Explicit splice balance maps were not converted at the RPC boundary

**Kind:** sdk-defect  
**Severity:** medium  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia-splice`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

Both splice handlers passed newBalances straight through with a type assertion, so decimal strings reached bigint arithmetic. Both now use the shared amount-record converter with participant-key validation.

## Impact

A JSON request with decimal balances failed conservation arithmetic.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Decimal newBalances are converted to atoms.

**Actual:** Fixed: amountRecord() is used for splice-in and splice-out.

**Evidence:**

- packages/omnia-host/src/api/methods.ts prepareSplice

## Where to fix

- `packages/omnia-host/src/api/methods.ts`

### Approach

Convert and validate explicit balance maps at the RPC boundary.

## Constraints (do not violate)

- Keys must match the participant set; balances non-negative.

## Acceptance criteria

- [ ] Decimal balance maps are accepted.
- [ ] Unknown keys are rejected.

## Tests that prove it
