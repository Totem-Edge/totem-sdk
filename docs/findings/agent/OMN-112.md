# OMN-112 — Allocation verification ignores reserved and risk-adjusted capital

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/liquidity-bond`, `@totemsdk/omnia-pool`
**Observed versions:** @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-pool@0.7.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-110
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-110 (liquidity-bond/src/allocation.ts:34-47)`

## Context

Available liquidity is computed as amount minus allocatedAmount. Reserved capital and the effective (risk-adjusted) amount are ignored, and allocatePositionCapital executes the channel or factory operation before checking whether the position is now overallocated.

## Impact

Capital can be committed beyond what the position can actually support; the check reports the overcommitment after execution.

## Reproduce

```bash
pnpm --filter @totemsdk/liquidity-bond test
```

**Expected:** Availability subtracts allocated and reserved, and is capped by effective value before execution.

**Actual:** Only allocatedAmount is subtracted, after execution.

**Evidence:**

- allocation.ts:34-47
- omnia-pool/src/allocate.ts:83-192

## Where to fix


### Approach

Compute headroom from effective minus allocated minus reserved before executing, and refuse the operation when it would overcommit.

## Constraints (do not violate)

- Do not add a post-hoc check in place of a pre-execution one.
- Preserve existing allocation bookkeeping.

## Acceptance criteria

- [ ] An allocation exceeding risk-adjusted headroom is refused before any channel operation.
- [ ] Reserved capital reduces availability.
