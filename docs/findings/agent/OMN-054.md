# OMN-054 — Liquidity deposits could be marked chain-confirmed without requiring confirmation

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia-pool`, `@totemsdk/chain-provider`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

The deposit verifier never set requireConfirmed, and evaluateDeposit only gated on confirmation when asked. The host now requires confirmation and a real depth (created vs tip), rejects verifier results that report confirmed:false, and the fallback path fails when depth cannot be established.

## Impact

An unconfirmed or reorg-prone coin could back an active liquidity position.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Only a coin confirmed at depth backs a position.

**Actual:** Fixed: confirmation and depth are mandatory at every funding check.

**Evidence:**

- packages/chain-provider/src/verify-deposit.ts
- packages/omnia-host/src/api/methods.ts depositToLiquidityPool

## Where to fix

- `packages/chain-provider/src/types.ts`
- `packages/chain-provider/src/verify-deposit.ts`
- `packages/omnia-host/src/api/methods.ts`

### Approach

Add minConfirmations/chainTip to the deposit contract and require them for liquidity funding.

## Constraints (do not violate)

- Never treat a positive MMR entry as depth.

## Acceptance criteria

- [ ] A mempool coin is rejected.
- [ ] Unknown depth is rejected.
- [ ] A deep coin is accepted.
