# CAN-020 — Factory opening requests the funding signature before the proposal exists (regression from CAN-010)

**Kind:** sdk-defect  
**Severity:** high  
**Status:** in-progress  
**Packages:** `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-host@0.13.4
**Source:** `re-audit R-003, verified against source at 5d8c427b`

## Context

prepareFactory builds the plan and immediately sends FACTORY_FUNDING_REQUEST; FACTORY_PROPOSAL is only sent later by submitFactory (and by createFactoryMethod after its own signer call). CAN-010 now requires the receiver to hold an accepted factory with a matching pendingCommitment before it will sign, which cannot be true yet. The two changes contradict each other, so a fresh two-host factory opening fails at the funding step.

## Impact

Factory opening is blocked on the prepared path and likely on the createFactory path. This is a functional regression introduced by the CAN-010 fix, not a pre-existing defect.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** prepare → sign → finalize completes against a second host.

**Actual:** The responder answers ERROR ("does not match any locally accepted factory") because it has not received the proposal yet.

**Evidence:**

- fix proposed in PR #222: both host paths send FACTORY_PROPOSAL first and use the acceptance as the funding witness
- packages/omnia-host/src/api/methods.ts:1455-1473 — funding request inside prepareFactory
- packages/omnia-host/src/api/methods.ts:1574 — FACTORY_PROPOSAL sent later in submitFactory
- packages/omnia-host/src/api/methods.ts:2752 — createFactory method requests the signature before its proposal too
- packages/omnia-host/src/peer-guards.ts:57-89 — resolveFactoryFundingTarget requires an accepted factory

## Where to fix

- `packages/omnia-host/src/api/methods.ts`
- `packages/omnia-host/src/lifecycle.ts`

### Approach

Reorder both flows so the proposal (with funding materials) establishes the pending factory before any funding signature is requested, and use the responder opening signature over the same commitment as the funding witness instead of a second round. Add a FACTORY_FINALIZED follow-up so the responder learns the funding txid after the proposer broadcasts.

## Constraints (do not violate)

- Do not relax CAN-010 back into an unbound signing oracle.
- Do not allow a second FACTORY_PROPOSAL to re-sign after acceptance.

## Acceptance criteria

- [ ] A two-host prepare → sign → finalize run completes and both sides hold the same funding txid.
- [ ] An unsigned/unknown digest is still refused.
