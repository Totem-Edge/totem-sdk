# OMN-006 — Multi-hop recovery does not journal the outstanding backward preimage duty

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-relay`, `@totemsdk/omnia-router`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-relay@0.7.1, @totemsdk/omnia-router@0.4.1, @totemsdk/omnia-host@0.13.4
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)

> Partially aliased: the dropped pendingRefunds overlap CAN-022 and the relay journal halves overlap CAN-008/CAN-009. The new part is the durable backward-preimage duty after fulfilHTLC.
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-006`

## Context

revealPreimage fulfils the incoming HTLC (changing signed state) before sending the update to the previous hop. If the send fails, the journal survives — but recover() clears any link whose incoming HTLC is no longer pending, which is now true, so the duty to propagate the preimage backwards is lost. Separately, the host multi-hop RPC throws on failure and discards the router's structured `pendingRefunds`.

## Impact

Reopened by the deeper audit: the final-recipient branch of forwardIncoming still fulfils the incoming HTLC and sends the preimage upstream without first journaling the delivery obligation, so a crash between fulfil and send is unrecoverable. A payment can be settled on the outgoing side and never settled backwards, leaving liquidity locked and the payer's HTLC stuck until timeout. Refund obligations are not reported to the caller.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-relay test
```

**Expected:** After a failed backward send, restart recovery still knows the preimage must be delivered to the previous hop.

**Actual:** The journal entry is removed because the incoming HTLC is terminal, and the preimage is never retried.

**Evidence:**

- packages/omnia-relay/src/forwarder.ts: fulfilHTLC then sendMessage then journal.remove
- packages/omnia-relay/src/forwarder.ts: recover() clears terminal incoming links
- packages/omnia-host/src/api/methods.ts: `throw new Error(result.error)` drops pendingRefunds

## Where to fix

- `packages/omnia-relay/src/forwarder.ts`
- `packages/omnia-relay/src/link-journal.ts`
- `packages/omnia-router/src/execute.ts`
- `packages/omnia-host/src/api/methods.ts`

### Approach

Journal distinct states (forward-intent, outgoing-signed, outgoing-accepted, preimage-received, backward-sent, peer-acked, complete) and replay them idempotently on restart. Return pending refunds to the caller on failure instead of dropping them.

## Constraints (do not violate)

- Do not clear a link until the backward settlement is acknowledged or provably terminal.
- Replay must be idempotent: no double settlement on repeated recovery.
- Keep the journal the single authority; do not infer from channel state alone.

## Acceptance criteria

- [ ] A crash after fulfilHTLC but before send leaves recoverable state that retries the backward send.
- [ ] Repeated recovery never settles the same HTLC twice.
- [ ] A failed multi-hop call surfaces pendingRefunds to the RPC caller.
