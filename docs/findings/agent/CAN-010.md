# CAN-010 — FACTORY_FUNDING_REQUEST signs an arbitrary peer-supplied digest

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-host@0.13.4
**Source:** `security audit OMN-NEW-004, verified against source at 8fa26907`

## Context

The FACTORY_FUNDING_REQUEST handler takes payload.digest, reserves a WOTS leaf, signs those exact bytes and returns the signature. It does not require an authorized pending factory, does not verify the proposed transaction, and does not bind the digest to a funding coin or to a locally initiated funding round. The host signs with the same tree it uses for other operations.

## Impact

A connected peer can use the host as a signing oracle: any 32-byte digest it chooses gets a valid WOTS signature, consuming key material. Whether a returned signature can authorize a malicious on-chain spend was not demonstrated end to end; the missing binding is the defect either way.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** A funding signature is produced only for a digest the host derived itself for a funding round it is part of.

**Actual:** The handler signs payload.digest after only checking that a local bundle exists.

**Evidence:**

- fix proposed in PR #218 (resolveFactoryFundingTarget binds the digest to an accepted factory and a participant peer)
- packages/omnia-host/src/lifecycle.ts:394 — onFactoryMessage returns early only if !factories || !localBundle
- packages/omnia-host/src/lifecycle.ts:410 — digest parsed from payload.digest
- packages/omnia-host/src/lifecycle.ts:418 — localBundle.signer.sign(digest, reservation.indices)

## Where to fix

- `packages/omnia-host/src/lifecycle.ts`

### Approach

Derive the digest locally from the pending factory proposal and funding coin, compare it to the request, and sign only on a match. Require an outstanding funding round with a known counterparty. Never sign an opaque digest supplied by a peer.

## Constraints (do not violate)

- Do not keep an arbitrary-digest path behind a flag.
- Do not reserve a leaf before the digest is validated (a rejected request must not burn key material).

## Acceptance criteria

- [ ] A request whose digest does not match the locally computed funding digest is rejected without reserving a leaf.
- [ ] A request with no outstanding funding round is rejected.
- [ ] The legitimate round still produces a valid signature.
