# OMN-007 — VTXO claim verification accepts a caller-supplied signer list

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-vtxo`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-vtxo@0.8.1, @totemsdk/omnia-host@0.13.4
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-007`

## Context

The claim policy evaluates membership in `witness.signers: string[]`, which is a list of names, not signatures. The host exposes `omnia/verifyVtxoClaim` and passes `params.signers`, the caller-chosen block height and HTLC status straight through, returning `success: true`.

## Impact

Any caller can obtain a "valid" claim result by asserting the right names and block. If an operator or integration treats that result as authorisation, a VTXO can be claimed without a signature.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Claim verification requires signatures over the canonical claim preimage and rejects a name list.

**Actual:** `{signers: ["beneficiary"], block: <cliff>}` returns valid without any signature check.

**Evidence:**

- packages/omnia-vtxo/src/claim-policy.ts: `witness.signers` membership tests
- packages/omnia-host/src/api/methods.ts: verifyVtxoClaim passes `params.signers` and `params.block`

## Where to fix

- `packages/omnia-vtxo/src/claim-policy.ts`
- `packages/omnia-host/src/api/methods.ts`

### Approach

Split the policy evaluator from verification. The host must verify signatures over the claim preimage before calling the policy, and take the block from the chain provider rather than the request. Rename the RPC result so it cannot be read as an authorisation.

## Constraints (do not violate)

- Do not accept a signer name list as evidence of a signature.
- The block height must come from chain state for the authoritative path.
- Keep the pure policy function usable for offline evaluation.

## Acceptance criteria

- [ ] A claim with no signature or a wrong signer signature is rejected by the host.
- [ ] A caller-supplied block that is ahead of the chain tip is ignored or rejected.
- [ ] The valid signed claim path still succeeds.
