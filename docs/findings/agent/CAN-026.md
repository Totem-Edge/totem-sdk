# CAN-026 — No scenario exercises omnia-lsp or omnia-lsp-provider

**Kind:** canary-coverage  
**Severity:** medium  
**Status:** open  
**Packages:** `@totemsdk/omnia-lsp`, `@totemsdk/omnia-lsp-provider`
**Observed versions:** @totemsdk/omnia-lsp@0.1.0, @totemsdk/omnia-lsp-provider@0.1.0
**Source:** `registry audit, 25 Nov 2026: grep -rln "omnia-lsp" artifacts/canary/src returns nothing`

## Context

Both LSP packages shipped in 0.1.0 and appear in no scenario, no profile and no gate. The Omnia audit of 25 November 2026 raised eight findings against them, including two P0 authorization and capital-exposure defects (OMN-066, OMN-067), all found by static review rather than by a run. The harness cannot observe a regression in the provider quote path because it never executes it.

## Impact

An LSP regression — forged quote accepted, provider amount unvalidated, false-positive host success — reaches a release with no canary evidence. The release gate can only block on what the register knows, and the register only learns about this package from external audits.

## Reproduce

```bash
cd artifacts/canary && pnpm run canary list | grep -i lsp
```

**Expected:** At least one scenario imports the LSP provider facade and drives a quote → open cycle.

**Actual:** No matches. Scenario ids stop at 49-omnia-two-peer-channel and none imports @totemsdk/omnia-lsp or @totemsdk/omnia-lsp-provider.

**Evidence:**

- artifacts/canary/src/scenarios contains no lsp scenario
- artifacts/canary/src/orchestrator/ScenarioRegistry.ts ALL_SCENARIOS has no lsp entry
- docs/findings/agent/OMN-066.md and OMN-067.md describe defects that a quote-tamper scenario would catch

## Where to fix

- `artifacts/canary/src/scenarios/50-omnia-lsp-quote-open.ts`
- `artifacts/canary/src/orchestrator/ScenarioRegistry.ts`
- `artifacts/canary/src/config/profiles.ts`
- `artifacts/canary/src/config/packageMatrix.ts`

### Approach

Add a local-simulated scenario that issues a quote through the provider facade against a fixed manifest, then asserts: (a) the issued quote verifies; (b) a mutated amount, fee or token is rejected; (c) a quote issued to one consumer cannot be redeemed by another; (d) an expired quote is refused; (e) a host returning undefined or an error-only object is reported as failure. Register it in ALL_SCENARIOS and a profile.

## Constraints (do not violate)

- Use the published packages, not a re-implementation of the policy.
- Do not assert current (defective) behaviour: the negative legs are expected to fail until OMN-066/067/070/071 close.
- No private keys or live funding in local-simulated mode.

## Acceptance criteria

- [ ] The scenario imports @totemsdk/omnia-lsp-provider and exercises quote() and openQuote().
- [ ] Every negative leg above is asserted.
- [ ] The scenario is registered, listed by `canary list`, and part of a profile.
- [ ] The package appears in the pin matrix so a version drift is visible.

## Definition of done

1. The defect is fixed at the layer named above — not worked around downstream, not masked in the canary.
2. The acceptance criteria above all hold, with tests that fail without the fix.
3. This finding's `status` is moved to `fixed` in `artifacts/canary/src/findings/registry.ts` with the fixing commit.
4. The canary re-runs clean and the pins are updated to the published patch version.
