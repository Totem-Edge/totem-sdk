# OMN-068 — LSP quotes are issued against advertised capacity with no durable reservation

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-lsp-provider`
**Observed versions:** @totemsdk/omnia-lsp-provider@0.1.0
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Depends on:** `OMN-067` — land those first.
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-066`

## Context

The admission policy documents that it does not reserve capacity and that the provider must re-check before co-signing. The facade implements neither the reservation nor the re-check: every quote() call is evaluated against the same static manifest, so N concurrent quotes can each be within capacity while their sum is not.

## Impact

Concurrent requests can collectively exceed available liquidity. Host-level coin selection bounds what can be funded on chain, but it does not enforce a commercial exposure limit and fails late, after a consumer has been given a signed commitment.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-lsp-provider test
```

**Expected:** Issuing a quote reserves its provider-side amount against a durable ledger, and the reservation is released on expiry, consumed on open and reconciled after restart.

**Actual:** Two quote() calls for the same asset at maxChannel both succeed; nothing records the first commitment.

**Evidence:**

- packages/omnia-lsp-provider/src/policy.ts:62-67 — the policy states it does not reserve capacity
- packages/omnia-lsp-provider/src/provider.ts:108-119 — quote() calls evaluation only
- packages/omnia-lsp-provider/src/provider.ts:132-151 — open()/openQuote() never re-check capacity

## Where to fix

- `packages/omnia-lsp-provider/src/provider.ts`
- `packages/omnia-lsp-provider/src/policy.ts`

### Approach

Add a reservation ledger keyed by quoteId with amount, expiry and state (reserved/consumed/released). Reserve on issue, release on expiry, consume atomically on open, and reconcile entries that outlive a restart. Capacity checks subtract outstanding reservations.

## Constraints (do not violate)

- Reservation state must be durable, not in-process memory.
- Expiry must use the provider clock, not the request's.
- A failed open must release, not leak, its reservation.

## Acceptance criteria

- [ ] Concurrent quotes cannot exceed the provider's per-asset exposure limit.
- [ ] An expired reservation stops counting against capacity.
- [ ] A restart re-reads outstanding reservations instead of resetting exposure.
- [ ] The open path re-checks capacity against the live ledger.
