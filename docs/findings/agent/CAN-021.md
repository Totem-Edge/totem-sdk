# CAN-021 — Watchtower starts but only observes; it never contests, fulfils or refunds

**Kind:** sdk-defect  
**Severity:** medium  
**Status:** open  
**Packages:** `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-host@0.13.4
**Source:** `re-audit R-004, verified against source at 5d8c427b`

## Context

CAN-014 wired the watch service into host start/close and stopped it mistaking updates for closes. Its host callbacks, however, only emit observations: no contest transaction, no HTLC fulfilment or timeout, no refund. A successful close notification also adds the channel to the processed set even though nothing protective ran.

## Impact

A unilateral close is detected but not answered before the contest deadline, so detection does not protect funds. The processed set can suppress later findings for a channel that is still at risk.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** A detected close triggers the protective action and records evidence of completion.

**Actual:** onUnilateralClose emits an observation and the channel is then marked processed.

**Evidence:**

- packages/omnia-host/src/lifecycle.ts:828-890 — watch callbacks emit observations only
- packages/omnia-host/src/watch.ts — closed set updated after the callback resolves

## Where to fix

- `packages/omnia-host/src/lifecycle.ts`
- `packages/omnia-host/src/watch.ts`

### Approach

Give the watch service a durable response state machine: explicit contest/fulfil/refund actions, deadline tracking, retries and completion evidence. Only mark a channel processed when the action succeeded.

## Constraints (do not violate)

- Do not mark processed on observation alone.
- Do not automate actions the custody mode forbids.

## Acceptance criteria

- [ ] A simulated unilateral close produces a contest action before the deadline.
- [ ] A failed action is retried and never marked complete.
- [ ] Restart resumes pending responses.
