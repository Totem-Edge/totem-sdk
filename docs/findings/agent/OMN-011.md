# OMN-011 — Channel graphs advertise every channel that is not closed

**Kind:** sdk-gap  
**Severity:** medium  
**Status:** open  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia-relay`
**Observed versions:** @totemsdk/omnia-host@0.13.4, @totemsdk/omnia-relay@0.7.1
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-011`

## Context

The routing provider filters `channel.status === 'closed'`, so funding_pending, quiesced and spliced channels are advertised as routable even though HTLC creation requires `active`. A path can be selected and then fail at lock time.

## Impact

Routes fail late, after a payment has been attempted; in-flight payments can be stranded.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Only `active` channels appear in the routing graph.

**Actual:** Every status except `closed` is advertised.

**Evidence:**

- packages/omnia-host/src/router/routing-provider.ts: `if (channel.status === 'closed') continue;`

## Where to fix

- `packages/omnia-host/src/router/routing-provider.ts`
- `packages/omnia-relay/src/forwarder.ts`

### Approach

Filter on the positive predicate (`active`) instead of excluding one terminal status, and share the predicate with the HTLC entry check.

## Constraints (do not violate)

- Do not change channel status values or the wire format.
- Spliced channels must rejoin the graph when they return to active.

## Acceptance criteria

- [ ] A graph built from mixed-status channels contains only active ones.
- [ ] A channel that returns to active is routable again.

## Tests that prove it

- `tests/unit/omnia-host/src/__tests__/routing-eligibility.test.ts`
