# OMN-084 — Forwarding admission is a check-then-write across awaits, not an atomic reservation

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-relay`
**Tracked as:** `CAN-016` — this id is the audit's alias; the canonical entry owns the fix.
**Observed versions:** @totemsdk/omnia-relay@0.10.0
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-082`

## Context

The forwarder checks the in-memory link set and the journal for a duplicate hashlock or incoming HTLC, then awaits and writes the intent in a separate operation. The journal serialises individual writes, so two concurrent forwards can both pass the duplicate check and the second write then overwrites the first entry.

## Impact

Duplicate forwarding admission. Other channel guards may prevent a doubled signature, but the forwarding journal — the record recovery depends on — is silently replaced, so one incoming HTLC can lose its outgoing association.

## Reproduce

```bash
cd artifacts/canary && pnpm run canary run 38-omnia-relay-phase-a
```

**Expected:** A reserveForward() operation performs the uniqueness check and the intent write in one atomic step.

**Actual:** Two concurrent forwards for one hashlock both observe no duplicate and both write an intent.

**Evidence:**

- packages/omnia-relay/src/forwarder.ts:219-243 — duplicate check, then awaits, then record(intent)
- packages/omnia-relay/src/link-journal.ts:75-87 — write is serialised but not check-and-reserve

## Where to fix

- `packages/omnia-relay/src/forwarder.ts`
- `packages/omnia-relay/src/link-journal.ts`

### Approach

Add a transactional reserveForward(intent) to the journal that fails if the hashlock or incoming (channelId, htlcId) already exists, and drive the forward path through it. Enforce uniqueness at the storage layer too.

## Constraints (do not violate)

- Uniqueness must hold across processes, not only within one journal instance.
- A retried forward must converge on the existing reservation, not create a second obligation.
- Keep the existing journal shape readable for recovery.

## Acceptance criteria

- [ ] Concurrent forwards for one hashlock admit exactly one.
- [ ] A duplicate reservation raises a typed conflict, not an overwrite.
- [ ] Recovery sees the same association the forwarder committed.
