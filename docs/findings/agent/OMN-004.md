# OMN-004 — Pool payout settlement is an unverified caller assertion

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/omnia-pool`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-pool@0.5.4, @totemsdk/omnia-host@0.13.4
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-004`

## Context

executePoolPayout correctly refuses to settle without evidence, but when `settlement` is supplied it stores it, marks the intent settled-externally, decrements capital and consumes the receipt without checking the evidence. The host casts the RPC parameter to the same type.

## Impact

A caller with pool-management access can advance accounting as if a payout happened. Whether that is theft depends on who can reach the RPC, but the accounting no longer reflects chain or channel reality.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-pool test
```

**Expected:** A settlement object that does not reference the withdrawal id, amount, recipient and pool is rejected and leaves the registry unchanged.

**Actual:** Any object is stored; the intention is marked settled and the receipt consumed.

**Evidence:**

- packages/omnia-pool/src/withdraw.ts: `if (!params.settlement) return …` then immediate settlement
- packages/omnia-host/src/api/methods.ts: `settlement: params.settlement as never`

## Where to fix

- `packages/omnia-pool/src/withdraw.ts`
- `packages/omnia-host/src/api/methods.ts`

### Approach

Verify finality before mutating: for `confirmed` check the transaction against the chain provider and the required depth; for `offchain-final` verify a signed settlement from the channel/factory. Bind the evidence to the exact withdrawal id, amount, recipient and pool.

## Constraints (do not violate)

- No unconditional settlement path, including through the host RPC.
- Do not accept a bare boolean or opaque object as finality.
- Keep the prepared-draft path unchanged for callers without evidence.

## Acceptance criteria

- [ ] Forged or mismatched settlement evidence leaves the registry byte-identical.
- [ ] A settlement for another withdrawal id, amount, recipient or pool is rejected.
- [ ] The valid confirmed and offchain-final paths still settle.
