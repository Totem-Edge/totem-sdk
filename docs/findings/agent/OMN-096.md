# OMN-096 — The watchtower treats a stale-state successor as channel continuity

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia`
**Observed versions:** @totemsdk/omnia-host@0.16.0, @totemsdk/omnia@4.0.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-094
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-094 (omnia-host/src/watch.ts:118-145)`

## Context

The watch service treated any unspent successor coin at the funding address as channel continuity. It did not compare the successor's sequence or state commitment with the latest signed local state, which is exactly the case a watchtower must contest. The contest callback also proved the original funding coin rather than the live successor.

## Impact

A counterparty publishing an older signed state can settle it unchallenged: the watcher never reports a close, and even if it did, the proof would be for a spent coin. This is the failure mode that makes eltoo watchtowers necessary.

## Reproduce

```bash
cd artifacts/canary && pnpm run canary run 23-chaos-recovery
```

**Expected:** A successor whose sequence is below the latest signed local state raises a contestable finding and contests the live coin.

**Actual:** Any successor was treated as continuity, and proofs were taken from channel.fundingCoinId.

**Evidence:**

- watch.ts:129-135 (successor => continuity)
- lifecycle.ts:1166 (exportCoin(channel.fundingCoinId))

## Where to fix


### Approach

Read the successor sequence from its state (port 101), compare with latestState.sequence, raise a contestable close when behind, and prove the live coin in the contest path.

## Constraints (do not violate)

- Do not contest normal updates (sequence >= local).
- Keep behaviour unchanged when the adapter cannot report a sequence.

## Acceptance criteria

- [ ] A stale successor produces a unilateral-close finding naming the live coin.
- [ ] The contest path proves the observed live coin.
- [ ] Scans do not overlap.
