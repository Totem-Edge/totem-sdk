# OMN-101 — A unilateral settlement broadcast is recorded as a completed closure

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/omnia`
**Observed versions:** @totemsdk/omnia@4.0.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-099
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-099 (omnia/src/settlement.ts:589-622)`

## Context

finalizeUnilateralClose broadcasts the settlement transaction and immediately calls markChannelClosed. Nothing verifies inclusion in the canonical chain, so an accepted-but-unconfirmed transaction yields a closed channel.

## Impact

The application reports closure and may stop watching while the transaction is absent or reorged, leaving funds in a state nobody monitors.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia test
```

**Expected:** Broadcast, confirmation and final closure are distinct states; closure requires chain evidence.

**Actual:** markChannelClosed follows the broadcast directly.

**Evidence:**

- settlement.ts:612 (markChannelClosed after broadcast)
- settlement.ts:695 (markChannelClosed)

## Where to fix


### Approach

Split the lifecycle into closing_unilateral → settlement_broadcast → settlement_confirmed → closed, with an injected chain verifier for the final transition.

## Constraints (do not violate)

- Do not mark closed without confirmation.
- Keep the broadcast id recoverable.

## Acceptance criteria

- [ ] An unconfirmed settlement is not closed.
- [ ] A reorg reopens monitoring.
- [ ] Closure requires verified inclusion.
