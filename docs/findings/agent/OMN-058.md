# OMN-058 — Factory unilateral exits enforce the original funding shares, not the latest signed factory state

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-factory`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/wots-lease@0.5.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

The factory timeout path paid the immutable funding split and authorized the spend with N-of-N signatures without checking the payout set. RFC-079 now implements two complementary settlement branches: per-party escape and an output-enforced full distribution that reads every share from PREVSTATE, pins the output count, destination, amount and total, and needs only one participant signature to trigger. Full distribution is funded by default, and checkpoint enforcement is on by default: the cooperative branch only accepts a checkpoint (same script, same value, sequence + 1), and off-chain allocation changes (virtual-channel open/close, reallocate) are refused until the change is committed as a checkpoint. The escapes therefore read the latest committed allocation, never a stale funding split.

## Impact

A broadcaster can no longer redirect, resize, drop or add a payout, and a participant can no longer move value off chain (VC open/close, reallocate) and then escape against the old share: those changes are refused until checkpointed. Remaining: the host does not yet submit the checkpoint transaction, so virtual channels are blocked on a checkpointed factory; newer uncommitted off-chain states still require the contest protocol; virtual-channel reserves are not distributable.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-factory test
```

**Expected:** Every committed factory transition has an enforceable recovery artifact for its latest allocation.

**Actual:** Redirected, resized, missing, extra and wrong-token payouts are rejected; one participant signature settles a valid distribution; a checkpointed factory refuses VC open/close and reallocate until the allocation change is checkpointed (tests/unit/omnia-factory/src/__tests__/distribution.test.ts, checkpoint.test.ts).

**Evidence:**

- packages/omnia-factory/src/factory.ts buildFactoryOpening
- packages/omnia-factory/src/script.ts escape branch
- packages/omnia-factory/src/virtual.ts allocations

## Where to fix

- `packages/omnia-factory/src/factory.ts`
- `packages/omnia-factory/src/script.ts`
- `packages/omnia-factory/src/virtual.ts`

### Approach

Per RFC-079: (a) output-enforced full distribution plus the per-party escape, both bound to the latest confirmed allocation (checkpoint mode); (b) the pre-signed compact mode is kept as a separate, clearly documented mechanism that does not verify allocations; (c) the contestable recovery protocol remains the target for uncommitted off-chain states.

## Constraints (do not violate)

- A payout set must be derived from PREVSTATE, never from a caller-supplied allocation map.
- Do not weaken the output checks to preserve an O(1) instruction claim.
- Refuse to distribute while a virtual channel still holds value.

## Acceptance criteria

- [ ] A signed virtual-channel payment is enforceable by the losing party on chain.
- [ ] Escape pays the latest signed allocation, not the original contribution.
