# OMN-058 — Factory unilateral exits enforce the original funding shares, not the latest signed factory state

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** open  
**Packages:** `@totemsdk/omnia-factory`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/wots-lease@0.5.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

buildFactoryOpening writes each participant original contribution into the funding coin share ports, and the timeout branch pays those ports. Virtual-channel opens, updates and closes change allocations off-chain with N-of-N signatures, and nothing updates the on-chain share ports. RFC-079 checkpoint mode now exists (buildFactoryCheckpoint + enforceCheckpoints covenant: same-script successor, advanced STATE(104), conserved value, pinned party root), so a deployment can make the escape pay the latest allocation. The default off-chain path still pays the original split, and the contestable protocol is not implemented.

## Impact

After an escape opens, a participant could reclaim their original allocation despite having transferred value away in signed virtual-channel updates. The recipient newer entitlement is not enforceable on chain.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-factory test
```

**Expected:** Every committed factory transition has an enforceable recovery artifact for its latest allocation.

**Actual:** Default mode: only the immutable initial split is enforceable. Checkpoint mode: the escape pays the latest checkpointed shares (tests/unit/omnia-factory/src/__tests__/checkpoint.test.ts).

**Evidence:**

- packages/omnia-factory/src/factory.ts buildFactoryOpening
- packages/omnia-factory/src/script.ts escape branch
- packages/omnia-factory/src/virtual.ts allocations

## Where to fix

- `packages/omnia-factory/src/factory.ts`
- `packages/omnia-factory/src/script.ts`
- `packages/omnia-factory/src/virtual.ts`

### Approach

Per RFC-079: (a) checkpoint mode is implemented and can be enabled per factory; (b) the target remains a versioned, challengeable protocol with independent recovery certificates and verified distribution outputs; (c) enabling checkpoints by default, or shipping the contest mode, is required before off-chain factory value can be called enforceable. A nominal fix that keeps paying original shares is rejected.

## Constraints (do not violate)

- Do not claim factory value is enforceable until a recovery artifact exists and is adversarially tested.
- Remove buildFactoryDistributionScript from the settlement path unless it verifies the distribution outputs.
- Checkpoint mode must stay opt-in until its deployment cost is documented for users.
- buildFactoryDistributionScript must not be presented as a latest-state payout verifier.

## Acceptance criteria

- [ ] A signed virtual-channel payment is enforceable by the losing party on chain.
- [ ] Escape pays the latest signed allocation, not the original contribution.
