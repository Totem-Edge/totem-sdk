# OMN-117 — VTXO split outputs can receive duplicate identifiers

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/vtxo`
**Observed versions:** @totemsdk/vtxo@0.10.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-115; fixed by validating output identifiers in split through a shared guard that merge now uses too; duplicate ids are refused rather than silently renamed
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-115 (vtxo/src/split.ts:24-53)`

## Context

splitVtxo checks that the amount and nonce arrays have equal length but not that output ids are unique. Splitting into equal amounts with identical nonces produces identical ids, and the proof map is keyed by id.

## Impact

Output records can overwrite each other or become ambiguous.

## Reproduce

```bash
pnpm --filter @totemsdk/vtxo test
```

**Expected:** Every split output identifier is unique within the batch.

**Actual:** Uniqueness is not enforced.

**Evidence:**

- split.ts:24-53

## Where to fix


### Approach

Reject duplicate output ids in split (the invariant OMN-046 applied to refresh).

## Constraints (do not violate)

- Apply the same invariant to every VTXO transformation.
- Do not silently rename outputs.

## Acceptance criteria

- [ ] A split with duplicate ids is refused.
- [ ] Merge/refresh/split share the uniqueness guard.

## Tests that prove it

- `tests/unit/vtxo/src/__tests__/multiparty.test.ts`
