# OMN-099 — Channel activation conflates funding depth with peer acceptance

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-host@0.16.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-097
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-097 (omnia-host/src/api/methods.ts:1351-1368, 1380-1414, 2814-2838)`

## Context

The read path promotes funding_pending and opening channels to active on funding depth alone, while resubmitChannelProposal promotes on acknowledgement without rechecking depth. Each condition is necessary but neither is sufficient.

## Impact

A channel can be advertised active with no counterparty record, or with an unconfirmed funding coin. Routing and payment then act on a channel that cannot settle.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Activation requires funding depth, an authenticated acknowledgement, and a persisted initial exit package.

**Actual:** Activation depends on whichever condition the caller last observed.

**Evidence:**

- methods.ts:2814-2838 (read-path promotion on depth)
- methods.ts:1380-1414 (resubmit promotes on ACK)

## Where to fix


### Approach

Introduce one activation gate that requires all conditions and is the only path to active.

## Constraints (do not violate)

- Keep pending states readable and recoverable.
- Do not make the ACK authoritative for on-chain state.

## Acceptance criteria

- [ ] A funded channel with no ACK is not active.
- [ ] An ACK without depth is not active.
- [ ] Activation is idempotent.
