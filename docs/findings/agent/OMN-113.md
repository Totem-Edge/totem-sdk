# OMN-113 — The recorded allocation amount is not bound to the executed operation

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-pool`
**Observed versions:** @totemsdk/omnia-pool@0.7.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-111; fixed by binding the execution target to the authorised amount: channel targets must sum localAmount+remoteAmount to it, vtxo and factory targets must declare the same amount, a created channel totalValue is checked, and a mismatch is refused before execution
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-111 (omnia-pool/src/allocate.ts:87-156)`

## Context

The registry amount comes from params.amount while the channel, factory or VTXO operation receives separate target parameters. Nothing verifies that the executed operation deployed the same amount, asset and ownership allocation.

## Impact

The registry can record an allocation that differs from what was actually deployed.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-pool test
```

**Expected:** Execution parameters are derived from the authorized allocation.

**Actual:** Accounting amount and execution target are independent inputs.

**Evidence:**

- allocate.ts:87-156

## Where to fix


### Approach

Derive the execution target from the allocation record; verify the resulting deployment before registering it.

## Constraints (do not violate)

- One source of truth for the amount.
- Do not trust caller-supplied target amounts.

## Acceptance criteria

- [ ] A mismatched execution target is refused.
- [ ] The recorded amount equals the deployed amount.
