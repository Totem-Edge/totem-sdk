# OMN-014 — Splice recovery can attach one observed successor to several pending splices

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-splice`
**Tracked as:** `CAN-012` — this id is the audit's alias; the canonical entry owns the fix.
**Observed versions:** @totemsdk/omnia-splice@0.3.2
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-014`

## Context

recoverInterruptedSplices now uses each record's own expected successor (address, token, amount) instead of one global observation, refuses to let two pending splices claim the same coin, rejects a successor that is not the coin already recorded for the splice, and persists the observed coin id while the successor is unconfirmed. The dead ternary is gone. Residual: the observed coin is bound by expected amount/address and the per-record coin id, not by a transaction-input proof.

## Impact

A channel can be marked active with a coin that belongs to a different splice, or two records cleared by one coin.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-splice test
```

**Expected:** Each pending splice recovers only its own successor.

**Actual:** Each record uses its own expected successor, a claimed-coin set prevents reuse, and a mismatched recorded coin is rejected (tests/unit/omnia-splice/src/__tests__/successor.test.ts).

**Evidence:**

- packages/omnia-splice/src/successor.ts: recoverInterruptedSplices loop
- packages/omnia-splice/src/successor.ts: no-op ternary in the rebroadcast result

## Where to fix

- `packages/omnia-splice/src/successor.ts`

### Approach

Bind the successor to the splice: require the transaction id or a spent-input link, exclude coins already claimed by another recovery record, and remove the dead ternary.

## Constraints (do not violate)

- Keep the CAN-012 ambiguity rejection.
- A coin claimed by one splice must not be reused by another.

## Acceptance criteria

- [ ] Two pending splices cannot both adopt one coin.
- [ ] Recovery either proves lineage or leaves the record funding_pending.
