# OMN-105 — Automated watcher actions bypass the channel mutation coordinator

**Kind:** sdk-defect  
**Severity:** high  
**Status:** in-progress  
**Packages:** `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-host@0.16.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-103; Scan single-flight landed with OMN-096; the action-path lock remains open.
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-103 (omnia-host/src/watch.ts:163-205, lifecycle.ts:1194-1289)`

## Context

The watch service executes settlement and HTLC timeout actions and writes the resulting channel state without acquiring the shared per-channel lock used by RPC and peer-message handlers. Its interval has no in-flight guard.

## Impact

A watcher action can interleave with an operator or peer-driven mutation on the same channel, producing concurrent state writes.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** Watcher actions take the same channel lock and reload state after acquiring it; scans are single-flight.

**Actual:** Scans were unsynchronised and the action path did not take the lock.

**Evidence:**

- watch.ts start() setInterval without guard
- lifecycle.ts onUnilateralClose

## Where to fix


### Approach

Route watcher actions through the channel coordinator, reload authoritative state, and single-flight scans.

## Constraints (do not violate)

- Do not deadlock with RPC callers.
- Leave findings unprocessed on lock contention so the next pass retries.

## Acceptance criteria

- [ ] A watcher action cannot run concurrently with an RPC mutation of the same channel.
- [ ] Scans never overlap.
