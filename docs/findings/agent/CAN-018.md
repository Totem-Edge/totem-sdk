# CAN-018 — Factory proposal still signs a peer-controlled commitment

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** in-progress  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia-factory`
**Observed versions:** @totemsdk/omnia-host@0.13.4, @totemsdk/omnia-factory@0.7.0
**Source:** `re-audit R-001, verified against source at 5d8c427b`

## Context

CAN-010 closed the FACTORY_FUNDING_REQUEST oracle by binding the digest to an accepted factory, but a second signing path remains. FACTORY_PROPOSAL carries a peer-supplied ChannelFactory; the host calls acceptFactory(factory), which converts factory.pendingCommitment to bytes and signs it. Nothing reconstructs the funding transaction or checks that the commitment is what this participant agreed to fund.

## Impact

A peer that can submit a proposal naming the local signer can solicit a WOTS signature over an attacker-chosen commitment. That signature is a factory funding witness, so it is the material that authorises spending the participant coin. Source-level finding; no exploit executed.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-host test
```

**Expected:** The commitment is derived locally from validated factory terms and funding transaction bytes; a proposal whose commitment does not match is rejected before a leaf is reserved.

**Actual:** acceptFactory signs factory.pendingCommitment exactly as supplied in the proposal.

**Evidence:**

- fix proposed in PR #222: proposal carries funding materials; the acceptor rebuilds the funding tx and signs only the derived commitment
- packages/omnia-host/src/lifecycle.ts:462 — FACTORY_PROPOSAL calls acceptFactory(payload.factory, localBundle)
- packages/omnia-factory/src/factory.ts:502 — acceptFactory takes factory.pendingCommitment
- packages/omnia-factory/src/factory.ts:517 — Buffer.from(factory.pendingCommitment, "hex") is signed by leaseSign
- no reconstruction of the funding draft in the accept path

## Where to fix

- `packages/omnia-host/src/lifecycle.ts`
- `packages/omnia-factory/src/factory.ts`

### Approach

Make the acceptor derive the commitment: rebuild the funding transaction from the proposal terms and funding materials with buildFactoryOpening, compare its pendingCommitment to the proposal, and sign only the locally derived value. Require the proposal to carry the funding materials it was built from.

## Constraints (do not violate)

- Do not sign a commitment that is only peer-supplied.
- Do not reserve a WOTS leaf before the commitment is verified.
- Keep the legitimate single-proposer flow working end to end.

## Acceptance criteria

- [ ] A proposal whose commitment differs from the locally rebuilt funding transaction is rejected.
- [ ] A legitimate proposal still produces an accepted factory with both opening signatures.
- [ ] Covered by a two-host prepare → sign → finalize test.
