# OMN-080 — Route validation checks each hop and never the path

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-router`
**Observed versions:** @totemsdk/omnia-router@0.5.0
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-078`

## Context

validateRoute() iterates route.hops and validates each in isolation. It does not require any hops, does not check that consecutive hops connect, does not check the route starts at the payer and ends at the requested recipient for the requested amount and asset, and does not check that amounts and token transitions are consistent along the path. executeMultiHopPayment() then locks only non-swap hops, so a swap-only route validates and settles nothing.

## Impact

An empty route returns { success: true, state: 'recipient-settled', settledHops: [] } — a payment reported as settled with no value moved. A route whose hops are individually valid but disconnected can also pass, so the payment fails partway with locks already placed.

## Reproduce

```bash
cd artifacts/canary && pnpm run canary run 13-omnia-router-single-hop
```

**Expected:** A route that does not begin at the payer, end at the recipient, transport the requested amount in a consistent asset, or contain hops at all is refused before any HTLC is locked.

**Actual:** validateRoute({ hops: [] }) returns ok, and executeMultiHopPayment returns success with settledHops [].

**Evidence:**

- packages/omnia-router/src/route-validation.ts:116-127 — loop over hops, no path invariant
- packages/omnia-router/src/execute.ts:112-140 — plainHops derived, empty loop skipped
- packages/omnia-router/src/execute.ts:194-239 — success returned with nothing settled

## Where to fix

- `packages/omnia-router/src/route-validation.ts`
- `packages/omnia-router/src/execute.ts`

### Approach

Validate the route against the payment request, not only the channel graph: non-empty, hop[i].to === hop[i+1].from, first hop starts at the payer, last hop ends at request.recipient for request.token/amount, amounts non-increasing after fees, and every token transition either identical or an explicit swap. Refuse a route with no executable hops.

## Constraints (do not violate)

- Do not change the channel-graph checks; add request-level invariants.
- An empty or non-executable route is a failure, never a success.
- Acceptance is bound to the PaymentRequest, not to a mutable hop object.

## Acceptance criteria

- [ ] An empty route is rejected.
- [ ] A disconnected route is rejected before the first lock.
- [ ] A route that does not deliver the requested amount and token to the recipient is rejected.
- [ ] A swap-only route cannot return success with no settlement.
