# OMN-120 — Routing advertisements include channels that are not active

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-relay`
**Observed versions:** @totemsdk/omnia-relay@0.11.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-118; fixed by advertising only active, funded channels as edges in both the relay and host routing graph builders; opening, funding-pending, closing and disputing channels are withdrawn on the next rebuild
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-118 (omnia-relay/src/routing.ts:58-89)`

## Context

The routing graph excludes only closed channels, so opening, funding-pending, disputing and closing channels appear as usable edges.

## Impact

Routes can be computed through channels that cannot carry a payment.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-relay test
```

**Expected:** Only active, verified, unencumbered channels are advertised.

**Actual:** Everything except closed.

**Evidence:**

- routing.ts:58-89

## Where to fix


### Approach

Require an active status allow-list plus funding verification.

## Constraints (do not violate)

- Do not advertise a channel before activation.
- Keep peers able to learn the channel exists without routing it.

## Acceptance criteria

- [ ] Non-active channels are not routable.
- [ ] A closing channel is withdrawn promptly.

## Tests that prove it

- `tests/unit/omnia-relay/src/__tests__/client.test.ts`
