# OMN-038 — Inbound HTLC validation compared the proposed state with itself

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/tx-builder@0.7.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia host audit, 2026-11-18 (verified against 51aed956)`

## Context

_handleStateUpdate replaced the persisted pendingHTLCs with the peer-supplied set before verifyStateForCoSign, so validateHtlcSet compared proposed HTLC terms with themselves. Verification now uses the persisted channel; the proposed set is only used for digest/signature construction.

## Impact

A counterparty could retain an HTLC id while changing its hashlock, timeout, amount or parties and still be co-signed.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia test
```

**Expected:** Verification receives the persisted HTLC set.

**Actual:** Fixed: verifyState/verifyStateForCoSign receives the original channel.

**Evidence:**

- packages/omnia/src/integration.ts _handleStateUpdate
- packages/omnia/src/sign.ts validateHtlcSet

## Where to fix

- `packages/omnia/src/integration.ts`

### Approach

Validate against the persisted channel and keep the proposed state only for digest construction.

## Constraints (do not violate)

- New HTLC ids remain valid; existing ids may only transition forward.

## Acceptance criteria

- [ ] A mutated existing HTLC term is rejected.
- [ ] A new HTLC is still accepted.

## Tests that prove it
