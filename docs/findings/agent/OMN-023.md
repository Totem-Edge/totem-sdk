# OMN-023 — Incoming splice proposals are co-signed without verifying the proposer signature or approval

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-host`, `@totemsdk/omnia-splice`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/omnia-vtxo@0.9.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia host signing audit, 2026-11-18 (verified against 997b7f40)`

## Context

onSpliceMessage calls acceptSplice directly. acceptSplice checks membership, quiescence, conservation and draft/params binding, but never verifies proposal.proposerSignature and has no spending approval. omnia-splice/src/coordination.ts verifies the proposer signature and enforces an approval decision; the host bypasses both.

## Impact

A counterparty can submit a correctly formed splice-out that redirects value to an address of its choice, and the host may supply the missing signature automatically.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-splice test
```

**Expected:** acceptSplice verifies proposal.proposerSignature and requires an authorised withdrawal/reallocation before signing.

**Actual:** acceptSplice signs the splice digest after parameter checks; the host calls it for any inbound SPLICE_PROPOSAL.

**Evidence:**

- packages/omnia-host/src/lifecycle.ts onSpliceMessage
- packages/omnia-splice/src/splice.ts acceptSplice (no proposer signature check / approval)
- packages/omnia-splice/src/coordination.ts (signature + approval path)

## Where to fix

- `packages/omnia-splice/src/splice.ts`
- `packages/omnia-host/src/lifecycle.ts`

### Approach

Move proposer-signature verification and an explicit authorisation callback into the signing boundary. Require a withdrawal/reallocation authorisation when the local entitlement decreases.

## Constraints (do not violate)

- Do not rely on the coordinator for a security property the signer needs.
- Verify the proposer signature over the same digest that is signed.
- Reject unauthorised economic changes before reserving a leaf.

## Acceptance criteria

- [ ] A proposal with an invalid/missing proposer signature is rejected before signing.
- [ ] A splice-out that reduces the local entitlement requires explicit approval.
- [ ] Honest proposals still complete.
