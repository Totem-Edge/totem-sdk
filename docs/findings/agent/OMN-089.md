# OMN-089 — markExited accepts any non-empty transaction id as proof of exit

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-vtxo`, `@totemsdk/omnia-host`
**Observed versions:** @totemsdk/omnia-vtxo@0.9.0
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-087`

## Context

markExited() requires status 'exiting' and a non-empty txpowId, then records the VTXO as exited. It does not verify that the transaction exists, is confirmed, succeeds, or pays the correct owner the correct amount.

## Impact

As an internal state reducer under a trusted caller this may be acceptable, but the exported API reads as completion of an exit. Any consumer treating 'exited' as verified settlement can be shown a fabricated exit.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-vtxo test
```

**Expected:** Broadcast, confirmation and final settlement are distinct states, and the final transition requires authoritative chain evidence.

**Actual:** markExited(vtxo, { txpowId: 'x' }) yields status 'exited'.

**Evidence:**

- packages/omnia-vtxo/src/exit.ts:33-59 — markExited

## Where to fix

- `packages/omnia-vtxo/src/exit.ts`

### Approach

Split the state machine: broadcast (tx id known), confirmed (buried), settled (verified payout). Require an injected chain witness for the confirmed and settled transitions, and rename the current function to make its trust level explicit.

## Constraints (do not violate)

- Do not rename a trusted reducer into a verifier without adding the verification.
- The final transition must be able to fail closed when the chain cannot be read.
- Keep existing stored VTXOs readable.

## Acceptance criteria

- [ ] An unconfirmed or unknown transaction cannot reach the settled state.
- [ ] The payout is verified against the expected owner and amount on the final transition.
- [ ] The API distinguishes local bookkeeping from verified completion.
