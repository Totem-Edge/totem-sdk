# OMN-110 — A liquidity position can become active without funding evidence

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/liquidity-bond`, `@totemsdk/omnia-pool`
**Observed versions:** @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-pool@0.7.0
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-108; fixed by deriving status and spendable amount from verified funding: an unfunded record is a draft with zero available liquidity, activation requires chain-confirmed funding that matches the position amount, and active/withdrawable listings require the same proof
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-108 (liquidity-bond/src/position.ts:11-63)`

## Context

createLiquidityPosition sets status to committed when funding exists and active when it does not, and falls back to the self-declared commitment amount when funding is not chain-confirmed. The exported activation helper rejects non-confirmed funding but permits absent funding. depositToPool verifies on chain; the underlying functions do not.

## Impact

A position with no backing can be active, allocatable and withdrawable through a path that bypasses depositToPool.

## Reproduce

```bash
pnpm --filter @totemsdk/liquidity-bond test
```

**Expected:** No position becomes active, allocatable or withdrawable without authoritative funding evidence.

**Actual:** status: funding ? committed : active.

**Evidence:**

- position.ts:20-27
- liquidity-bond/src/registry.ts:168-183

## Where to fix


### Approach

Require chain-confirmed funding for active/allocatable status at the position and registry layer, not only in depositToPool.

## Constraints (do not violate)

- Do not break the deposit path.
- Keep unfunded records representable as non-active.

## Acceptance criteria

- [ ] An unfunded position cannot be listed as withdrawable.
- [ ] The amount always comes from verified funding.

## Tests that prove it
