# OMN-051 — Splice transactions encoded atom amounts as whole MINIMA

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-splice`, `@totemsdk/core`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-vtxo@0.9.0, @totemsdk/omnia-pool@0.6.0, @totemsdk/liquidity-bond@0.4.0, @totemsdk/omnia-router@0.4.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/chain-provider@0.4.0, @totemsdk/core@1.6.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Deeper Omnia covenant/transaction audit, 2026-11-18 (verified against 51aed956)`

## Context

spliceDraftToMinimaBytes passed atom integers as decimal strings to the core JSON serializer, which encodes an integer string at scale zero. Every splice amount was therefore 10^44 too large. Amounts are now converted with atomsToAmount at the boundary.

## Impact

Splice-in and splice-out transactions encoded economically incorrect values; agreement between the parties did not detect it.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-splice test
```

**Expected:** A 0.2 MINIMA amount round-trips as 0.2, not 2e43.

**Actual:** Fixed: decimal MINIMA is encoded and verified by deserializeTransaction.

**Evidence:**

- packages/omnia-splice/src/splice-tx.ts spliceDraftToMinimaBytes
- packages/core/src/transaction-json.ts serializeTransaction

## Where to fix

- `packages/omnia-splice/src/splice-tx.ts`

### Approach

Convert atom amounts to canonical decimal strings before the core serializer.

## Constraints (do not violate)

- Never pass an atom integer to a decimal-MINIMA API.

## Acceptance criteria

- [ ] Fractional, whole and custom-token amounts round-trip byte-exactly.
