# OMN-008 — Vesting policy never enforces the vested amount before the end block

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-vtxo`
**Observed versions:** @totemsdk/omnia-vtxo@0.8.1
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia whole-family re-audit (2026-11-17), finding OMN-008`

## Context

The vesting case checks the cliff, then `if (ctx.block >= endBlock) return valid`; before the end block it computes `elapsed` and `span` and never uses them, returning valid for any positive `claimAmount`. The maximum vested amount at the current block is therefore never enforced.

## Impact

A beneficiary can claim the entire vesting allocation immediately after the cliff. This is direct value loss for any VTXO using the vesting policy.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-vtxo test
```

**Expected:** At block `< endBlock`, a claim above the linear vested amount is rejected.

**Actual:** Any `claimAmount > 0` is accepted once the cliff is reached.

**Evidence:**

- packages/omnia-vtxo/src/claim-policy.ts: vesting branch returns `total > 0n ? {valid:true} : …`
- packages/omnia-vtxo/src/claim-policy.ts: `elapsed`/`span` computed but unused

## Where to fix

- `packages/omnia-vtxo/src/claim-policy.ts`

### Approach

Compute the vested amount as a function of block (`cliff`, `startBlock`, `endBlock`) and reject a claim above it; use the elapsed/span values that are already derived. Make the cliff and end blocks explicit in the result so callers can display the schedule.

## Constraints (do not violate)

- Do not remove the cliff check.
- Partial claims before the end block must remain possible up to the vested amount.
- Do not change the policy shape without a migration note.

## Acceptance criteria

- [ ] A claim above the vested amount at the current block is rejected.
- [ ] A claim at or below the vested amount succeeds.
- [ ] At/after endBlock the full amount is claimable.
