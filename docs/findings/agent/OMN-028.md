# OMN-028 — Repeated settlement requests can exhaust WOTS signing capacity

**Kind:** sdk-defect  
**Severity:** medium  
**Status:** fixed  
**Packages:** `@totemsdk/omnia`
**Observed versions:** @totemsdk/omnia@3.0.0, @totemsdk/omnia-host@0.14.0, @totemsdk/omnia-factory@0.7.2, @totemsdk/omnia-splice@0.3.4, @totemsdk/omnia-vtxo@0.9.0
**Origin:** Totem Edge Omnia whole-family re-audit, 2026-11-17 @ `c81af31` (verified in source)
**Source:** `Omnia host signing audit, 2026-11-18 (verified against 997b7f40)`

## Context

The peer settlement handler called signSettlementRequest on every matching request, allocating a fresh lease even for identical channel/sequence/digest. A replay cache keyed by channel/sequence/digest now reuses the response and rejects a conflicting settlement for the same sequence, with an optional durable store wired to the host state store. A dedicated regression test and full durable approval policy remain.

## Impact

A counterparty could previously consume one-time signing capacity without completing a settlement.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia test
```

**Expected:** Identical requests reuse the stored co-signature; conflicting requests are rejected.

**Actual:** Replay defense implemented in integration.ts; regression test still to add.

**Evidence:**

- packages/omnia/src/integration.ts _handleSettlementProposal
- packages/omnia/src/settlement.ts signSettlementRequest

## Where to fix

- `packages/omnia/src/integration.ts`

### Approach

Persist the signed response by canonical digest+participant, return the same response for idempotent retries, reject conflicting requests, and enforce a bounded signing policy.

## Constraints (do not violate)

- Do not burn a leaf for a replayed request.
- Reject a different settlement for the same channel+sequence.

## Acceptance criteria

- [ ] Repeat request returns the same signature.
- [ ] Conflicting request is rejected.
- [ ] Durable store survives restart.
