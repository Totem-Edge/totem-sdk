# OMN-066 — An LSP open quote is executed without verifying its signature, terms or policy

**Kind:** sdk-defect  
**Severity:** critical  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-lsp-provider`, `@totemsdk/omnia-lsp`
**Observed versions:** @totemsdk/omnia-lsp-provider@0.1.0
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Depends on:** `OMN-071` — land those first.
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-064`

## Context

openQuote() checks only that the quote has not expired and that providerId matches the manifest, then passes the quote straight to the funding host. It does not verify the quote signature, recompute the terms hash from the quoted fields, re-run the admission policy, or bind the quote to the caller. Any caller that can reach this method can therefore present a quote the provider never signed.

## Impact

If the facade is exposed through an untrusted API, a forged or modified quote can initiate a provider-funded channel on terms the provider never approved. Downstream host limits bound the loss, but the LSP authorization boundary itself is absent, so the provider's commercial policy is advisory.

## Reproduce

```bash
pnpm --filter @totemsdk/omnia-lsp-provider test
```

**Expected:** openQuote() rejects a quote whose signature does not verify over the canonical terms, whose termsHash does not match the quoted fields, or whose terms no longer satisfy the current policy.

**Actual:** A hand-built quote with signature 'x', an inflated remoteAmount and a stale termsHash is passed to host.openChannel and the host is asked to fund it. Only expiresAt and providerId are inspected.

**Evidence:**

- packages/omnia-lsp-provider/src/provider.ts:140-151 — openQuote checks expiresAt and providerId only
- packages/omnia-lsp-provider/src/quote.ts:111-116 — signOpenQuote attaches the signature and nothing consumes it on the way back in
- packages/omnia-lsp/src/quote.ts:152-170 — quoteMatchesManifest compares identity fields, not the signature or terms hash

## Where to fix

- `packages/omnia-lsp/src/quote.ts`
- `packages/omnia-lsp-provider/src/provider.ts`

### Approach

Recompute termsHash from the quoted fields, verify the provider signature over it with the manifest's identity key, require quote.consumerPartyId/consumerPublicKeyDigest to equal the authenticated caller, re-run evaluateOpenRequest against current policy and capacity, and consume the issued quote id atomically before calling the host.

## Constraints (do not violate)

- Do not accept a structurally valid quote as authentic: signature verification is mandatory, not optional.
- Structure the API so the unverified path cannot be reached by accident (make raw openQuote internal).
- Do not weaken the check for local testing; inject a test signer/clock instead.

## Acceptance criteria

- [ ] An unsigned, re-signed-by-another-key, or field-mutated quote is rejected before the host is called.
- [ ] A quote issued to one consumer cannot be redeemed by another caller.
- [ ] Replaying an already-consumed quote id is refused.
- [ ] A quote that no longer satisfies policy is refused even when its signature is valid.
