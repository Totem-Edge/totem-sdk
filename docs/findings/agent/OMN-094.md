# OMN-094 — HTLC fulfilment receipts are not bound to the authenticated transition that paid them

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia`, `@totemsdk/omnia-pool`
**Observed versions:** @totemsdk/omnia@3.0.0
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-092`

## Context

The receipt builder reads amount and fulfilment status from the channel's historical HTLC records, and the verifier authenticates a supplied signed state with the recipient's signature. Neither establishes that the specific transition from the preceding authenticated state fulfilled that HTLC and moved the stated amount.

## Impact

Receipt verification cannot stand alone as a financial earn-proof boundary. A receipt can be produced for an amount the transition did not actually transfer, which undermines the pool fee accounting that consumes it (see OMN-083).

## Reproduce

```bash
pnpm --filter @totemsdk/omnia test
```

**Expected:** Verification checks the authenticated predecessor and successor states, the HTLC identity, the preimage commitment, the exact balance delta and both parties' authorization.

**Actual:** A receipt whose amount differs from the state delta still verifies against a validly signed successor state.

**Evidence:**

- packages/omnia/src/htlc.ts:63-122 — receipt build and verify
- amount and status sourced from channel.pendingHTLCs, not from the state delta

## Where to fix

- `packages/omnia/src/htlc.ts`

### Approach

Carry the predecessor and successor state hashes in the receipt, derive the amount from the balance delta between them, include the hashlock/preimage commitment and both signatures, and verify all of it.

## Constraints (do not violate)

- Do not trust the historical HTLC record for the amount.
- Version the receipt format; old receipts must not silently pass the new verifier.
- Verification must fail closed when the predecessor state is unavailable.

## Acceptance criteria

- [ ] A receipt whose amount does not match the state delta fails.
- [ ] A receipt for an HTLC absent from the transition fails.
- [ ] A missing counterparty signature fails.
- [ ] Downstream fee accounting refuses an unverified receipt.
