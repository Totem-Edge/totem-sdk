# CAN-002 — Manifest proofs are not bound to the manifest they attest

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/proof`, `@totemsdk/manifest`
**Observed versions:** @totemsdk/proof@1.0.3, @totemsdk/manifest@2.1.0
**Source:** `artifacts/canary/src/composition/__tests__/ProofAndMoney.test.ts`

## Context

verifyManifestProof verifies the manifest signature and the proof envelope independently and never compares them. A proof whose payload.manifestId names a different manifest, a proof of a different kind (attestation), and a proof issued by an unrelated key all verify as valid against any correctly signed manifest.

## Impact

An attestation issued for one manifest can be presented as attestation for another (for example a later version with the same appId), and a non-manifest proof can be passed off as a manifest attestation. Verifiers that rely on the pairing will over-report assurance.

## Reproduce

```bash
cd artifacts/canary && pnpm composition
```

**Expected:** A proof for manifest A is rejected against manifest B, a non-manifest proof is rejected, and a foreign issuer is rejected.

**Actual:** All three return valid: true, because verifyManifestProof never reads proof.payload, proof.kind or the proof issuer relative to the manifest.

**Evidence:**

- packages/proof/src/manifest-proof.ts: verifyManifestProof = verifyManifest(signedManifest) then verifyProof(signedProof)
- createManifestProof stores payload { manifestId } from the caller, and nothing compares it back
- canary observed: proof for A vs manifest B -> valid; attestation proof vs manifest A -> valid; proof with unrelated manifestId -> valid; proof from a third-party issuer -> valid

## Where to fix

- `packages/proof/src/manifest-proof.ts`
- `packages/manifest/src/id.ts`

### Approach

Bind the pair explicitly: require proof.kind === 'manifest', require the proof issuer to be the manifest author address, and compare payload.manifestId with the identifier computed from the supplied manifest. Decide and document which identifier that is (content digest via computeManifestId is the strongest; appId is weaker and would still allow version substitution), then make createManifestProof derive it from the SignedManifest rather than trusting a caller string.

## Constraints (do not violate)

- Do not change the manifest signing format or computeManifestId semantics.
- Do not accept a wildcard or "any" manifestId to preserve callers.
- Keep verifyManifest false-paths and reasons unchanged.

## Acceptance criteria

- [ ] verifyManifestProof rejects a proof issued for a different manifest (version substitution).
- [ ] verifyManifestProof rejects a proof whose kind is not manifest.
- [ ] verifyManifestProof rejects a proof whose issuer does not match the manifest author.
