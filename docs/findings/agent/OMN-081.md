# OMN-081 — Consecutive HTLC deadlines differ by one block in multi-hop and cross-token execution

**Kind:** sdk-defect  
**Severity:** high  
**Status:** fixed  
**Packages:** `@totemsdk/omnia-router`
**Observed versions:** @totemsdk/omnia-router@0.5.0
**Origin:** Omnia SDK audit — 25 November 2026 @ `9f882c8` (verified in source)
**Source:** `Omnia SDK audit — 25 November 2026, reporter finding OMN-079`

## Context

Both execution paths derive each hop's timeout as expiryBlock - i (and - pos++ in the cross-token path). The gap between adjacent hops is therefore exactly one block, independent of the channel contest period, confirmation policy or the time an intermediary needs to claim or refund.

## Impact

An intermediary can be left unable to claim an outgoing HTLC before it must refund the incoming one, or unable to act at all under network disruption. The safety margin the protocol depends on is one block.

## Reproduce

```bash
cd artifacts/canary && pnpm run canary run 36-omnia-real-multi-hop
```

**Expected:** The expiry delta is derived from the channel contest delay plus the confirmation and recovery requirements, and is validated as sufficient before locking.

**Actual:** Hops are one block apart regardless of contestDelayBlocks (normally 256).

**Evidence:**

- packages/omnia-router/src/execute.ts:168 — expiryBlock - BigInt(i)
- packages/omnia-router/src/execute.ts:413,429,454 — expiryBlock - BigInt(pos++)

## Where to fix

- `packages/omnia-router/src/execute.ts`
- `packages/omnia-splice/src`

### Approach

Compute the required delta from the channel's contest delay and the recovery policy, expose it as a policy input with a safe default, and refuse a route whose available expiry window cannot fit every hop.

## Constraints (do not violate)

- Never reduce the existing spread.
- The delta must come from channel terms the router can verify, not a caller-chosen constant.
- A route that cannot fit the window is rejected, not truncated.

## Acceptance criteria

- [ ] Consecutive HTLC deadlines are separated by at least the contest delay plus the recovery margin.
- [ ] A route with insufficient expiry window is refused before locking.
- [ ] Both execution paths use the same derivation.
