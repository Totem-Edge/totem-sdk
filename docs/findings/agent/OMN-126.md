# OMN-126 — The TxPoW work verifier fails open when parsing fails

**Kind:** sdk-defect  
**Severity:** high  
**Status:** open  
**Packages:** `@totemsdk/txpow`
**Observed versions:** @totemsdk/txpow@1.1.1
**Origin:** Omnia adversarial audit — 26 November 2026 @ `c818f5e` (verified in source)

> reporter id OMN-124
**Source:** `Omnia adversarial audit — 26 November 2026, reporter finding OMN-124 (txpow/src/verify.ts:234-265)`

## Context

When the parser cannot establish the TxPoW structure, verifyTxPoWWork hashes the raw bytes as a proxy identifier and evaluates it against a floor difficulty, so the result can be valid for input that is not a TxPoW.

## Impact

Any admission or relay path that relies on this result can accept a malformed payload.

## Reproduce

```bash
pnpm --filter @totemsdk/txpow test
```

**Expected:** A structural parse failure returns valid: false on the authoritative path.

**Actual:** A fallback hash can satisfy the floor.

**Evidence:**

- txpow/src/verify.ts:234-265

## Where to fix


### Approach

Return invalid on parse failure; keep any lenient behaviour behind an explicit opt-in.

## Constraints (do not violate)

- Do not let a fallback produce validity.
- Keep diagnostics available.

## Acceptance criteria

- [ ] Malformed input is invalid.
- [ ] A well-formed TxPoW still verifies.
