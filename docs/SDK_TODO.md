## minima-rpc — cover the full Hawk node command set  *(DONE)*

`@totemsdk/minima-rpc` now ships generated metadata for all **132** node
commands (`packages/minima-rpc/src/commands.generated.ts`, generated by
`scripts/generate-minima-rpc-commands.mjs` from the RFC-0011 command reference).
Known commands validate required/unknown parameters and enums, coerce
booleans/numbers/JSON values, and preserve schema order. Unknown commands still
use the explicit passthrough path.

The old 1024-char `sanitizeRpcValue` cap is gone; the limit is now 10 MB with
whitespace/control-character rejection retained, so a full TxPoW payload on
`txnminepost data:<hex>` is accepted. `newaddress modifier:` remains an explicit
extension because the node manifest does not advertise it.

## minima-rpc transport — node RPC line endings  *(OPEN — fix at source)*

The hawk node's RPC response uses **LF** line endings by default
(`HTTP/1.1 200 OK\n…`), which is non-compliant; Node's `fetch` (undici) rejects
it (`HPE_INVALID_HEADER_TOKEN`) and even `node:http` fails ("Missing expected CR
after response line"). `curl` tolerates it, which hid the problem. The node can
emit CRLF with `-rpccrlf`.

**Task:** do **not** paper over this in the SDK (e.g. a tolerant/raw fallback).
Resolve it at the source so the SDK talks to a compliant server:
- **node-side:** make CRLF the default (HTTP requires it), so any standard client
  works without a flag; keep `-rpccrlf` as a no-op/deprecated.
- The SDK's `postCommand` must remain a strict, correct HTTP client — the
  existing `raw-http` fallback exists for genuinely unparseable servers, not as a
  standing workaround for a fixable defect.

## omnia swarm — `_stream.onData is not a function`  *(FIXED)*

`_adaptConn` treated any object with a `send` method as an `IStreamTransport`; a
raw Hyperswarm/streamx connection can expose `send` without the interface's
`onData`, so `OmniaStream` threw `_stream.onData is not a function`. Now detects
on `onData` and wraps otherwise (commit `0716615`).

## Node RPC compatibility  *(FIXED — node-side)*

Two node-side RPC defects blocked standard HTTP clients (Node undici). Both are
fixed at source in the hawk node (not worked around in the SDK):
- LF → **CRLF** line endings (default), and CRLF the 401/413 bodies.
- **case-insensitive `Content-Length`** header match (undici sends lowercase).

These are recorded here because they were discovered via the SDK's real client;
if similar defects recur, fix them in the node, not with an SDK fallback.

## Verification harness — package-scoped tests  *(use these commands)*

Workspace packages publish `dist/`, which is gitignored. A root `pnpm -r build`
or a single root Jest config therefore either rebuilds everything (including
nondeterministic WASM) or fails to resolve siblings on a fresh checkout. The
supported path is dependency-scoped:

```bash
pnpm install --frozen-lockfile
pnpm --config.verify-deps-before-run=false --filter "@totemsdk/<pkg>..." run build
pnpm --config.verify-deps-before-run=false --filter @totemsdk/<pkg> test
```

- Root `jest.config.js` is now an aggregator over `packages/*/jest.config.*`; it
  is a convenience runner, not the verification gate.
- Hidden/additional tests must live under the target package's `src/__tests__/`
  (or `src/**/*.test.ts`) so that package's transform, `moduleNameMapper` and
  `paths` apply.
- `omnia-host` maps its direct workspace deps to source; a fully build-free run
  still needs dependency `dist/` for transitive subpath imports.
